# 개념·문항·난이도 커리큘럼 — 운영 v2

문제는 목표까지 배우는 경로와 수준 판단을 실행하는 자원이다. 현재 단일 학습 시작·Python/SQL 독립 트랙·기본 목표와 추가 학습·기존 기록 보존을 유지한다.

## 운영 원본과 출시 순서

1. 목표 행동과 선수 지식을 [공통 설계 기준](CURRICULUM_DESIGN.md)에 따라 분해한다.
2. [문제별 경로](../backend/learning_paths.json)에 기초·적용·전이·선수 문항·보충 경로·과제 유형군을 작성한다. 모든 응용에는 같은 개념의 낮은 단계가, 전이에는 적용 단계가 연결되어야 한다.
3. [설계 카드](../curriculum/problem_bank.json)에 목표·힌트·오답 가설·진단·보충·변형·복습과 작성자 검토 상태를 남긴다.
4. 실제 라이브러리/SQLite로 참조 출력과 경계를 검증하고 원본·카드·경로의 일치를 확인한다. 미검수·누락·순환·보류 문항을 필수로 요구하는 경로는 게시를 차단한다.
5. 같은 원본을 웹/서버에 내보내고, 공통 이력의 수준·추천·선택 이유와 기록 호환을 검증한 뒤 최신 main에 통합·게시한다.

문항별 편집 난이도 원본은 [difficulty.json](../backend/difficulty.json)이다. 수준 1은 기초 확인, 2는 연결 적용, 3은 조건 변화·전이다. 추론 단계·코드 부담·전이·오개념 강도는 작성자 추정이며 실제 성과로 검증한 수치가 아니다. 풀이 전 힌트를 노출하지 않는 [문항 편집 기준](CONTENT_GUIDELINES.md)을 따른다.

## 사용자 수준과 다음 단계

상세 규칙과 임계값은 [운영 학습 경로·수준 판단](ADAPTIVE_LEARNING.md)과 경로 원본의 rules를 따른다. 개념별로 독립 해결 문항 수, 과제 유형, 서로 다른 날짜, 이미 푼 문제의 지연 복습, 도움 후 회복을 구분한다. 같은 날 문제 수를 여러 날의 근거로 바꾸지 않으며 풀이 속도를 감점하지 않는다.

선수 이해를 확인한 뒤 응용을 제시하고, 이미 충분한 근거가 있는 개념의 기초를 반복 강제하지 않는다. 기초가 없다는 이유로 응용의 최소 난이도를 올려 우회하지 않는다. 도움 받은 개념의 기초를 우선하고 새 세션의 이유·버전·근거를 학습 이벤트에 보관한다. 기존 묶음과 답안 snapshot은 바꾸지 않는다.

## 현재 자원과 아직 확인하지 않은 효과

현재 보관 211문항, 활성 Python 158개·SQL 48개이며 서술형 5개는 보류한다. 영역별로 pandas 56, NumPy 48, SQL 49, 통계 22, scikit-learn 36개다. 기존 배포 문항을 변경하지 않고 경로의 기초 다원화·적용 심화·활성 전이 확장을 위해 49개(초기 경로 보충 21개 + 전 개념 기초 다원화·전이 심화 28개)를 추가했다. 이후 [10월 19일 보강](content_batches/2026-10-19-expansion.md)에서 기존 119문항과 운영 규칙을 보존하며 18개 개념에 적용 9개·전이 9개를 추가했다. 모든 18개 개념에 서로 다른 기초 유형이 2개 이상 있고 모든 개념에 활성 적용·전이 단계가 연결된다.

[10월 20일 별도 보강](content_batches/2026-10-20-expansion.md)은 정기 5문항을 포함한 기존 142문항·선수 경로·운영 규칙을 보존하며 12개 개념에 적용 5개·전이 7개를 추가했다. 호출 순서·관측 단위·중간 객체·평가 독립성의 차이를 검수한다.

별도의 전처리 초안 17개는 운영 문제와 구별하며 추가 편집 검토 전이다. 이전 독립 알고리즘 실험은 보존하고 운영은 v2 단일 경로를 사용한다. 실제 휴대폰 장기 사용과 학습 효과는 개발·가상 검증과 구분한다. 새 자료로 선수 경로와 임계값을 보정할 때 [누적 기록](CURRICULUM_LOG.md)과 WBS 증거를 함께 남긴다.

## 2026-10-28 Python 기초 트랙과 SQL 확장 (CR-017)

[검수 기록](../curriculum/reviews/2026-10-28-tracks.json)은 기존 226개·전체 경로·카드(release_path_version 포함)·rules·review·기록 계약을 보존하고 새 ID 66개를 더한다. 별도 트랙 Python 기초(`python-basics`, 문항 domain `Python`)는 값과 연산자·문자열·리스트를 뿌리로 조건과 반복 → 함수와 인자, 리스트 → 튜플과 언패킹 → 딕셔너리, 리스트 → 집합, 함수와 튜플 → `*`와 `**` 펼치기 → 데코레이터 `@`로 이어지는 개념 10개·45문항(기초 20·적용 15·전이 10)이다. 개념마다 서로 다른 기초 유형 2개를 두고, 반복이나 함수 문법을 쓰는 적용·전이 문항은 그 개념의 문항을 `requires`로 건다. SQL에는 문자열·날짜 함수, 윈도 함수, 데이터 변경과 제약 개념(16문항)과 MIN·MAX·조건 없는 조인(2문항)을, 데이터 분석에는 NumPy 행렬곱 `@`(2문항)과 pandas `query`의 `@변수`(1문항)를 더했다. 출력 예측은 32/66(48%)이며 나머지는 줄 고르기 8·모두 고르기 24(빈칸·같은 결과·해석·목적·조건 변화)·순서 맞추기 1·조건 변화 객관식 1이다. 정답을 모르는 별도 검수자가 66개를 실행 없이 다시 풀어 모두 일치했고, 정답 위치 쏠림·힌트의 원인 줄 노출·지문의 단서·휴대폰 폭 지적을 반영했다. 추천 규칙은 learning-paths-2.3 그대로이며, 가상 재생에서 SQL은 이전 엔진과 결과가 같았다([비교](experiments/tracks-cr017-20261028.json)). 꾸준히 맞히는 학습자는 약 4주 안에 기초 45문항을 모두 보므로 클래스·예외·반복자 묶음이 다음 단계다.
