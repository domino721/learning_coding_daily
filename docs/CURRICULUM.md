# 개념·문항·난이도 커리큘럼

사용자는 ‘오늘 학습 시작’ 한 경로로 들어온다. 형식은 문항 작성자가 정하며 Python 데이터 분석/SQL 트랙별 신규 묶음에서 객관식·단답형만 추천한다. 서술형은 안정화 전 보류한다. 이미 진행한 묶음의 문제·형식·제출·힌트·문항 원본은 바꾸지 않는다.

## 편집 기준과 보정

문항별 입력 원본은 `backend/difficulty.json`이다. `concept_id`, `response_mode`, `level`, `reasoning_steps`, `code_load`, `transfer`, `distractor_strength`, `rationale`, `calibration`을 각 문항에 명시한다. `src/curriculum.json`은 이 원본과 Python 콘텐츠를 내보낸 결과이므로 직접 수정하지 않는다.

| 항목 | 기준 |
| --- | --- |
| 수준 1 · 기초 확인 | 핵심 연산/개념을 직접 읽거나 짧은 빈칸으로 확인 |
| 수준 2 · 적용 | 여러 연산·조건을 연결하거나 개념을 새 입력에 적용 |
| 수준 3 · 조건 변화·전이 | 축·메모리·분모·자료 구성·평가 절차가 달라진 상황을 판단 |
| 추론 단계 1~4 | 정답까지 연결해야 하는 의미 있는 추론 수 |
| 코드 부담 1~3 | 코드/자료 구조를 읽는 부담. 초기 코드 길이 기준을 편집 검수 |
| 전이 1~3 | 직접 확인 → 연결 적용 → 조건이 달라진 상황 |
| 오개념 강도 0~3 | 객관식 오답의 구분 부담. 직접 입력/서술형은 0 |

이는 **초기 편집 난이도**이며 실제 정답률로 검증된 수치가 아니다. 답변 형식을 바꾼 것만으로 수준을 올리지 않는다. 속도만으로 난이도를 낮추지 않는다. 사용자 백업의 익명화된 요약 자료가 쌓이면 문항별 첫 시도·힌트·해설·풀이 시간 분포를 보고 보정한다. 원본 답안과 로그를 외부로 자동 전송하지 않는다.

## 학습 규칙 v1

- 18개 개념과 선행 조건은 `backend/curriculum.py`의 CONCEPTS, 브라우저는 같은 내보내기를 사용한다. 선행 순환을 테스트한다.
- Python은 pandas·NumPy·통계·scikit-learn 기초를 섞고, SQL은 SQL 개념만 기초부터 시작한다. 별도의 모드/수준 선택이나 진단 절차를 요구하지 않는다.
- 정답 완료·첫 제출·힌트 없음·서술형이 아님을 모두 충족해야 독립 풀이로 센다. 이전 기록도 같은 조건으로 보수적으로 해석한다.
- 같은 개념은 하루의 첫 관찰만 사용한다. 같은 날 여러 번 풀어도 근거가 늘지 않는다. 시간 정보가 없으면 묶음 순서를 사용하고 실제 시각을 만들어 넣지 않는다.
- 서로 다른 문항 2개를 서로 다른 날 혼자 풀면 추천 단계 2, 다른 문항 3개·서로 다른 날 3일·수준 2 이상 독립 풀이 2일을 충족하면 단계 3이다.
- 기초를 혼자 한 번 풀면 수준 2 적용 확인을 허용한다. 같은 기초를 다른 날 회상한 경우에도 전이 탐색을 한 문제 허용하지만 이를 숙련 승급으로 표시하지 않는다. 새 수준 3 문항은 한 묶음에 최대 한 개다.
- 최근 서로 다른 두 날에 도움이 필요했다면 추천 단계를 한 단계 낮추어 보완한다. 서술형 해설 비교는 승급/강등 근거로 쓰지 않는다.
- 도움·재시도·해설 학습은 1일 뒤, 첫 독립 정답은 3일 뒤, 다른 날 독립 복습은 7일·14일 뒤 후보가 된다. 같은 날 반복만으로 복습 간격을 늘리지 않는다.
- 기본 5문제에서 예정 복습은 최대 3개, 나머지는 선행 조건과 난이도에 맞는 미학습 문항을 영역별로 섞는다. 추가 학습은 가능한 미학습 문항 우선이다. 같은 날 제시한 ID(미완료·이전 통합 포함)는 제외하고, 복습 기한 전 반복으로 채우지 않는다. 후보가 1~4개면 그 개수로, 0개면 소진 안내로 빈 세션 생성을 막는다. 5문제는 목표이고 상한이 아니다.
- 객관식은 두 번까지 제출한다. 두 번째 오답이면 `incorrect`로 완료하고 정답·해설 공개 및 다음날 복습이다. 첫 오답·힌트 후 성공은 독립 정답으로 세지 않으며 중복 제출 ID 재시도는 기회를 더 쓰지 않는다.
- 서술형 5개는 신규 추천에서 제외한다. 기존 서술 답안/임시 답안은 그대로 보관하며 ‘보류·미채점’으로 표시한다. 기존 완료 결과는 변경하지 않는다.
- 새 트랙 ID는 `python`/`sql`, 이전 `pandas` 통합 기록은 그대로 열람·비서술형 이어하기를 제공한다. Python 정답이 SQL 선행 조건이나 추천 단계를 높이지 않는다.

## 현재 범위

이전 검수 원본 60문항에 Codex의 2026-10-17 배치 5개를 추가해 65문항이다. 현재 활성 풀은 Python 48개·SQL 12개(60개)이며 서술형 5개는 보류한다. pandas 17, NumPy 12, SQL 13, 통계 11, scikit-learn 12개다. 날짜별 배치와 검수 근거는 backend/content_batches 및 docs/content_batches에 보관한다. 신규 문항은 다중 조건·축 보존·복사/뷰·외부 조인·집계의 NULL·비율의 분모·평가 전처리 등 변형 상황을 다룬다. Python/SQL 참조 실행은 저장소가 작성한 코드에만 적용한다. 사용자 코드를 실행하지 않는다.

Python·EDA·시각화·심화 모델링 전체를 이 65문항으로 포괄한다고 주장하지 않는다. 문항별 기록과 실제 사용 자료를 확보한 뒤 범위를 확장한다.
