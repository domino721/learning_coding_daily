# 매일 코딩 한 걸음 — 제품·개발 설계 v0.2

## 목표와 가설
매일 짧은 연습을 통해 코딩·데이터 분석 지식을 실제로 꺼내 쓸 수 있게 만든다. 어학 앱의 짧은 일일 분량, 간격 반복, 단계적 난이도라는 개념을 참고하며 콘텐츠와 UI는 독자적으로 만든다.

사용자가 확정한 요구: 매일 일정량, 단계별 성장, 지루하지 않은 구성, 한 문제에 긴 시간이 들지 않는 학습. **모바일 중심으로 출시까지 고려하며, 우선 본인이 사용한다. Python 기초를 알고 하루 10~15분 학습한다.**

- 앱에서 학습 트랙을 선택한다: pandas·실무 분석 / 코딩테스트 / 통계 분석. 제품 버전을 별도로 배포하기보다 하나의 앱에서 트랙과 개념별 진도를 분리한다.
- 첫 구현·콘텐츠 검증은 pandas·실무 분석에 집중한다. 준비되지 않은 트랙은 학습을 시작시키지 않고 준비 중으로 표시한다. 트랙을 바꿔도 기존 진도를 보존한다.
- 모바일 우선 반응형 웹으로 검증하고 설치 메타데이터를 제공한다. 아직 오프라인 학습과 푸시 알림은 지원하지 않는다. 앱스토어 배포는 학습 흐름 검증 후 Capacitor 등의 패키징 또는 네이티브 전환 필요성을 판단한다.
- 하루 10~15분, 3~5문제. 1문제 1~3분, 완주보다 이해를 우선한다.
- 모바일에서는 선택·빈칸·오류 찾기를 기본으로 하고 코드 입력은 1~3줄부터 시작한다. 표는 작은 행 수로 제공하고 키보드가 열린 상태의 화면·초점·터치 영역을 검증한다.
- 첫 버전은 개인용. 공개 출시 전에 인증·진도 동기화·개인정보 정책을 준비하며 가입·결제·랭킹·AI 문제 생성은 초기 범위에서 제외한다.

## 학습 경험
1. 목표와 현재 수준을 선택한다. 3~5개 짧은 진단 문제는 건너뛸 수 있고 첫 세션 결과로 보정한다.
2. 오늘의 카드에서 예상 소요 시간과 학습 개념을 확인한다.
3. 쉬운 복습 1개 → 새 개념 1~2개 → 적용 1개 → 마무리 회상 1개를 기본 구성으로 한다. 학습 기록이 없으면 기초부터 시작한다.
4. 결과 예측 → 빈칸 채우기 → 오류 수정 → 3~8줄 직접 작성으로 자유도를 늘린다. 타이핑 속도를 실력과 혼동하지 않는다.
5. 제출 직후 결과와 짧은 이유를 보여준다. 실패한 테스트에는 최소 입력과 기대 결과를 제공한다.
6. 90초쯤 막혔을 때 힌트를 제안하고 3분쯤이면 작은 단계로 나누거나 해설을 보고 나중에 재도전할 수 있다. 강제 시간 제한은 두지 않는다.
7. 오늘 배운 개념과 다음 복습을 보여준다. 연속 출석보다 주간 학습일과 개념 숙련도를 강조한다.

문제 소재는 주문·매출·로그·실험 데이터 등으로 바꾸되 한 문제는 한 개념에 집중한다. 새로운 문법과 어려운 도메인 지식을 동시에 요구하지 않는다. 시간이 긴 종합 문제는 선택 도전으로 분리한다.

## 난이도와 복습 — 초기 규칙
복잡한 머신러닝 대신 설명 가능한 규칙으로 시작한다. 수준은 전체 점수 하나가 아니라 개념별로 저장한다.

- 상태: 미학습 → 학습 중 → 복습 중 → 안정. 오답·힌트 사용 시 같은 개념의 더 쉬운 변형으로 돌아간다.
- 최근 서로 다른 문제 3개를 힌트 없이 맞히고 다음날 복습도 성공하면 다음 단계 후보로 올린다. 첫 성공만으로 숙련 처리하지 않는다.
- 풀이 시간은 보조 신호다. 탭 비활성 시간은 제외하고 느리다는 이유만으로 강등하지 않는다.
- 복습 간격 초깃값: 1일, 3일, 7일, 14일. 실패하면 다음날 재검토한다. 실제 데이터로 조정한다.
- 일일 복습은 최대 3개, 전체는 최대 5개. 복습이 많으면 새 문제를 줄인다. 놓친 날의 분량을 누적 의무로 만들지 않는다.
- 정답·소요 시간·힌트 단계·시도 횟수·건너뛰기를 기록하되 개인 식별 정보는 최소화한다.

## 콘텐츠 구조와 커리큘럼
트랙 → 개념 → 수준 → 문제 변형으로 구성한다. 예: pandas / 행 필터링 / 기초 / 주문 금액 조건.

| 단계 | 공통 Python | pandas·실무 분석 | 알고리즘 확장 |
| --- | --- | --- | --- |
| 1 | 자료형, 인덱스, 조건 | DataFrame 읽기, 열 선택 | 배열, 문자열 |
| 2 | 반복, 함수 | 필터링, 정렬, 결측치 | 해시, 정렬 |
| 3 | 작은 변환 함수 | groupby, merge, 날짜 | 스택·큐, 탐색 |
| 4 | 검증과 디버깅 | 지표 정의, 집계 함정 | 이분 탐색, 기초 DP |
| 5 | 짧은 실전 조합 | 통계량, 표본·편향, 실험 해석 | 선택형 종합 문제 |

출시 후보는 한 트랙의 5개 개념 × 6개 변형 = 30문제다. 직접 제작한 작은 데이터셋을 쓰고 문제별 정답·오답 이유·힌트 2단계·참조 풀이·경계 사례·예상 시간을 검수한다. 검수 전 문제를 자동 추천에 넣지 않는다.

## 기술 구조
- 프런트엔드: React + TypeScript + Vite. 현재 모바일 홈·트랙 목록·일일 문제·힌트·결과·최근 기록 화면을 구현했다.
- API·콘텐츠 도구: Python 3.12 + FastAPI + pandas. API 스키마는 OpenAPI로 확인 가능.
- 저장: SQLite 스키마 v1으로 세션·문제 상태·제출·문제별 복습일을 저장한다. 다중 사용자 운영 시 인증과 PostgreSQL을 검토한다.
- 모델: Concept(prerequisites), Exercise(version, type, concept, difficulty, time, hints), Attempt(answer, outcome, hints, active_seconds), Mastery(concept, state), Review(due_at), DailySession(date, exercise_ids).
- 일일 세션은 사용자 시간대 기준 날짜로 생성하고 같은 날 재접속해도 구성을 유지한다. DB 시각은 UTC, 화면 일자는 사용자 시간대 사용.
- 인증·외부 API·비밀키 없이 로컬 개발 가능. AI 호출은 필수 의존성이 아니다.

### 자유 코드 실행의 별도 경계
현재 답안 API는 선택지만 비교하며 사용자 코드를 실행하지 않는다. 이후 직접 작성 문제는 브라우저 Pyodide Web Worker를 먼저 검증한다. 고정 pandas 버전과 데이터, 중단 가능한 Worker, 실행 시간·출력 크기 제한을 검증해야 한다. 브라우저 판정은 개인 연습용이며 공정한 서버 검증을 보장하지 않는다. 다중 사용자 서버 채점이 필요해지면 별도 격리 실행 환경에서 네트워크·파일 접근·CPU·메모리를 제한한다. API 프로세스 안에서 eval/exec 또는 단순 subprocess로 사용자 코드를 실행하지 않는다.

## 단계별 진행과 완료 기준
1. **완료: 설계와 개발 기반** — 문서, 잠금 파일, 모바일 화면·설치 메타데이터·API 연결, build와 테스트.
2. **완료: 학습 세로 흐름** — 트랙 목록과 pandas 문제 10개, 일일 5문제, 선택·빈칸 제출, 2단계 힌트·해설, SQLite 기록, 새로고침·서버 재시작 후 이어하기. 중복 제출·한국 시간 자정 변경·동시 요청·10문제 참조 풀이 검증을 포함한 서버 테스트 8개와 모바일 Chromium 테스트 2개 통과.
3. **반복 학습** — 30문제, 개념별 숙련도·복습 스케줄·힌트. 오답 후 난이도와 다음 복습일이 설계대로 바뀌는 테스트 통과.
4. **짧은 코드 작성** — Worker 실행 가능성 확인 후 에디터·실행·중단·오류 피드백. 무한 반복과 큰 출력에서도 UI가 복구되는지 검증.
5. **사용성 검증** — 1주간 실제 사용. 문제별 중앙 풀이 시간, 3분 초과 비율, 힌트 후 성공률, 다음날 복습 성공률, 주간 재방문을 관찰. 목표 범위는 문제별 1~3분이며 사용자 실측으로 조정한다.
6. **확장** — 사용 결과를 본 뒤 통계 분석/알고리즘 트랙, 가입·동기화·배포를 결정한다.

## 확정 사항과 후속 결정
사용자 답변으로 모바일 우선·개인 사용 후 출시·트랙 선택 구조·pandas 우선·하루 10~15분·Python 기초 수준을 확정했다. iOS/Android 출시 우선순위와 수익화는 초기 학습 검증 이후 결정한다. 현재 5개 개념의 pandas 문제 10개를 포함한다.

## 현재 구현의 범위와 다음 작업
- 첫 트랙만 시작할 수 있고 나머지는 준비 중으로 표시한다. 사용자 계정·트랙별 사용자 프로필은 아직 없다.
- 완료 시 힌트/오답/해설 이력이 있으면 다음날, 처음부터 혼자 맞혔으면 3일 뒤 복습일로 저장한다. 하루 복습 최대 3개와 새 문제를 섞어 총 5문제로 만들고, 콘텐츠가 부족하면 다시 연습 문제로 채운다. 고급 개념 숙련도·1/3/7/14일 간격 확장·자동 난이도 조절은 미구현이다.
- 날짜는 서버의 APP_TIMEZONE(기본 Asia/Seoul) 기준이다. 개인용 서버 기록이며 로그인·사용자 분리·기기 간 동기화는 아직 없다.
- 풀이 시간은 제출 시점까지 화면이 활성화된 시간으로 기록한다. 제출 없이 닫으면 그 구간의 시간과 입력 중 답안은 저장하지 않는다. 진단·90초 힌트 자동 제안은 후속 작업이다.
- 10문제 정답은 pandas 참조 연산으로 자동 검증했다. 예상 시간과 난이도는 실제 사용으로 보정해야 한다.
- 다음 개발 범위는 30문제로 확장하고 개념별 숙련도와 복습 간격을 도입하는 단계다.

## 무료 휴대폰 사용 경로
사용자가 휴대폰 링크로 바로 사용하고 무료로 시작하기를 선택했다. GitHub Pages용 `web` 빌드 모드를 추가해 Python 서버 없이 기존 기능을 제공한다. 학습 기록은 해당 기기의 브라우저에 저장한다. 동일한 문제 원본을 JSON으로 내보내 서버·웹 콘텐츠를 일치시킨다. 서버/SQLite 모드는 유지하며, 두 모드 사이의 진도 이동과 다중 기기 동기화는 후속 과제다. Pages 게시 설정과 배포 성공 여부는 클라우드 환경 게시와 별도로 확인한다.
