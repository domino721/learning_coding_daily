## 출시 전에 만드는 커리큘럼

각 목표 문항에 기초 → 적용 → 조건 변화의 선수 경로를 작성한다. 응용 목표에는 같은 개념의 더 낮은 단계 문항이 필요하다. 기초가 없는 개념을 높은 최소 난이도로 우회해 바로 제시하지 않는다.

예를 들어 전처리 목표는 학습 호출의 반환 → 저장한 평균 → 저장한 표준편차 → 학습 값 변환 → 새 입력 변환으로 연결한다. 배열에서 값을 꺼내는 기초도 연결한다. NumPy 연산·메모리, SQL 연결, pandas, 통계에도 같은 기준을 적용한다.

`export-content.py`는 전체 문제의 카드·경로·버전·원본 일치, 선수 누락·순환·미검수와 낮은 단계 경로 누락을 검사한다. 새 문항은 개별 검토 완료 카드가 있어야 게시할 수 있다. 기존 공개 70문항의 내용은 보존하며 이미 검수된 원본과 난이도 근거를 가져온 카드 중 추가 오답 가설 검토가 필요한 상태도 표시한다. 현재 카드가 존재한다는 사실을 모든 문항의 추가 편집 검토나 학습 효과 검증으로 해석하지 않는다.

## 수준 측정

수준은 개념별로 판단한다. 초기에는 추천 단계 1과 ‘진단 전’을 표시하며 실제 능력을 확정하지 않는다.

1. 첫 시도 정답·힌트 없음·서술형 아님을 독립 해결로 센다. 현재 문항과 버전이 다른 기록은 승급 근거에서 제외하고 원래 기록은 보존한다. 동일 세션·문항·버전의 중복은 한 번만 센다.
2. 독립 관찰 일수는 하루에 한 번만 센다. 서로 다른 문항 수와 날짜 수를 구분하여, 같은 날의 여러 독립 해결은 문항 수에는 반영하되 여러 날의 근거로 바꾸지 않는다. 처음에 도움을 받고 나중에 독립 해결한 경우 그 성공도 관찰하되 하루 횟수는 늘리지 않는다.
3. 서로 다른 문항 2개·서로 다른 날 2일·서로 다른 과제 유형군 2개면 추천 단계 2다. 같은 과제의 숫자만 바꾼 변형으로 다양성을 부풀리지 않는다.
4. 다른 문항 3개·3일·수준 2 이상 독립 해결 2일·과제 유형군 3개와, 이미 푼 같은 문항의 다른 날 독립 복습을 모두 확인해야 단계 3이다.
5. 최근 오답·힌트·재시도·해설은 그날 첫 답 이후의 결과까지 확인한다. 도움이 필요하면 기초 보완을 우선하고, 이후 서로 다른 문항 2개의 독립 해결로 보충 표시를 해제한다. 과거의 성공 기록은 지우지 않는다.
6. 풀이 속도는 감점하지 않는다. 이유 설명의 자동 평가, 검증된 능력 점수나 정답 확률을 제공하는 모델은 아니다.

유형군은 작성자의 초기 분류이며 실제 사용자 자료로 보정해야 한다. 유형 수·관찰 일수·지연 복습 여부·보충 필요를 학습 기록에 표시한다.

## 사용자에게 맞는 다음 단계

새 묶음에서 해당 문항의 선수 문항을 독립 해결했는지 확인한다. 충분한 서로 다른 날·과제의 근거로 같은 개념 단계 2 이상이 확인되고 보충 중이 아니면 선수 이해를 잠정 인정해 불필요한 기초 반복을 줄인다.

보충 중에는 막힌 문항보다 한 단계 아래까지만 추천하되(단계 1·2에서 막히면 기초, 단계 3에서 막히면 적용까지) 아직 독립 해결하지 않은 과제 유형군을 우선한다. 보충의 우선권은 한 묶음에서 개념당 회복에 필요한 문항 수(`recovery_items`=2)까지다. 기초를 독립 해결한 개념은 다른 미학습 상위 문항의 필수 선수가 아닌 예비 기초 문항을 유예하고, 다음 날 새로운 과제 유형군의 적용(단계 2) 탐색을 우선 허용하며, 충분한 근거가 쌓이면 조건 변화(단계 3) 문항을 한 묶음 최대 1개 제공한다. 같은 날 한 개념에만 편중되지 않도록 개념을 분산하며, 아직 제시하지 않은 문제를 맞혔다고 가정해 선수를 해제하지 않는다.

예정 복습은 기본 묶음에서 2개(틀리거나 도움 받은 문항이 더 많으면 최대 4개, 2.3), 나머지는 해당 트랙의 새 적격 문항을 제공한다. 도움 받은 개념의 기초를 우선하며 영역을 섞는다. 새 적격 문항이 모자라면 남는 자리를 기한이 된 복습으로 채운다(2.3). 같은 날 제시한 ID·기한 전 반복으로 채우지 않고 그래도 부족하면 짧은 묶음이나 소진 안내를 유지한다. 추가 학습을 막는 하루 상한을 만들지 않는다.

복습은 도움 뒤 1일, 첫 독립 성공 뒤 3일, 다른 날 연속 독립 복습 뒤 7일이다. 다른 날 연속 3번 독립 해결한 문항은 복습에서 졸업한다(2.3). 서술형은 신규 추천과 독립 근거에서 제외하고 기존 답안은 보관한다.

learning-paths-2.1(2026-10-25, CR-013): 기한이 된 문항을 독립 해결한 지 7일(`review.repeat_gap_days`)이 지나지 않았으면 같은 문항을 다시 내지 않는다. 대신 같은 개념의 아직 풀지 않은 적격 문항을 보충 문항 → 같은 단계 → 카탈로그 순으로 골라 ‘다시 연습’(practice)으로 제시하고, 같은 개념의 복수 기한 문항은 한 자리만 쓴다. 대체 후보가 없으면 원래 문항을 복습으로 낸다. 도움·오답 뒤의 다음날 복습은 원래 문항을 그대로 다시 푼다(선수 보충 뒤 목표 재도전 유지). 7일이 지난 문항은 원래 문항으로 복습하며 단계 3의 지연 회상 근거가 된다. 추가 학습은 간격 안의 문항을 건너뛴다. 원래 문항의 due·streak는 그대로 두므로 기록 계약이 바뀌지 않는다. 베타 사용자의 “같은 문제가 단답형으로 반복된다” 후기를 근거로 하며 실제 체감 변화는 관찰로 확인한다.

learning-paths-2.2(2026-10-27, CR-015): 선택 규칙 세 가지를 바꾸고 임계값(`rules`)·복습 간격·하루 구성은 그대로 둔다.

1. **한 단계 아래 보충.** 단계 3(전이) 문항에서 도움을 받으면 기초(단계 1)로 되돌리지 않고 적용(단계 2)까지 보충 후보로 연다. 보충 정렬은 막힌 문항보다 한 단계 아래를 먼저 고른다. 단계 1·2에서 막힌 경우는 2.1과 같다. 개념 상태의 `support_level`이 막힌 문항의 단계를 기록한다.
2. **보충 우선권은 회복에 필요한 만큼.** 2.1은 보충 개념의 문항이 다른 모든 후보보다 앞서 한 묶음 다섯 자리를 한 개념이 모두 차지할 수 있었다. 2.2는 개념당 `recovery_items`(2)개까지만 보충 우선권을 주고, 나머지 자리는 다른 개념과 같은 기준으로 고른다.
3. **과제 형식 섞기.** 정렬 키의 마지막 동점 처리 직전에 ‘이번 묶음에 같은 과제 형식이 몇 개 있는지’를 넣어, 다른 조건이 같으면 덜 나온 형식을 고른다. 형식은 경로의 `task_form`이며, 없는 기존 문항은 코드에 빈칸(`____`)이 있으면 빈칸 채우기, 아니면 출력 예측으로 읽는다. ‘다시 연습’ 대체 문항은 보충 문항 → 원래 문항과 다른 형식 → 같은 단계 → 카탈로그 순으로 고른다. 선수·단계·개념 분산보다 앞서지 않는다.

가상 비교(`python3 scripts/compare-engines.py --base <2.1 commit>`, 결과 [learning-paths-v2.2.json](experiments/learning-paths-v2.2.json)): 같은 문항 은행에서 2.1과 2.2 선택 규칙만 바꿔 21일·42일을 재생했다. 모두 맞히는 학습자는 단계 결과가 같고, 묶음당 서로 다른 형식이 Python 기준 1.43→2.05개로 늘었다. 단계 3에서 처음 막히는 학습자는 42일 뒤 단계 3 개념이 5→10개로 늘고 기초 보충 문항이 45→11개로 줄었지만, 21일 시점의 단계 2 이상 개념은 13→10개로 초기 탐색이 느려졌다. 가상 이력이며 실제 학습 효과는 WBS-520/530에서 확인한다.

learning-paths-2.3(2026-10-28, CR-016): 같은 문항의 끝없는 반복을 끝내고 하루 묶음의 복습 비율을 낮추며, 그 때문에 밀리는 복습을 처리한다. 2.2까지는 독립 해결을 이어 가도 같은 문항이 14일마다 끝없이 돌아왔고, 복습 3자리가 계속 차서 모두 맞히는 학습자도 8일째부터 매일 5문제 중 3문제가 이미 푼 문항이었다.

1. **졸업.** 진도의 `streak`(다른 날 연속 독립 해결 수)가 `review.graduate_streak`(3) 이상인 문항은 기본·추가 학습의 기한 복습 후보에서 빠진다. 첫 해결 → 3일(7일 안이면 ‘다시 연습’) → 7일 복습을 모두 혼자 맞히면 졸업이다. 도움·오답은 `streak`을 0으로 되돌리므로 졸업이 늦어진다.
2. **보완 중에는 예외.** 개념이 보완 중(`needs_support`)이면 졸업한 문항도 기한이 되면 다시 낸다. 보완 해제에는 막힌 뒤 서로 다른 문항 2개의 독립 해결이 필요한데, 다른 문항이 모두 졸업한 개념은 그 근거를 얻지 못해 ‘기초 보완 중’에 머물렀다(가상 90일 재생에서 4개 개념).
3. **복습 2자리.** 기본 묶음의 복습 자리는 `review.daily_slots`(2)이다. 3자리일 때보다 새 문항이 하루 1개 늘어 하루 비율이 낮아진다.
4. **밀린 복습 처리.** 자리를 줄이면 복습이 더 밀린다(2.3 초안 가상 재생: 1/4 확률로 도움을 받는 학습자의 다음날 재도전이 평균 16일 늦어짐). 그래서 세 가지를 함께 둔다. (가) 기한 복습은 틀리거나 도움 받은 문항(`streak` 0)을 먼저 내고, 그다음 기한 순이다. (나) 그런 문항이 2개보다 많으면 복습 자리를 그 수만큼 `review.max_daily_slots`(4)까지 늘려 새 문항을 최소 1개 남긴다. (다) 새 적격 문항이 모자라 묶음이 5개를 못 채우면 남는 자리를 기한 복습으로 채운다(추가 학습과 같은 방식, 7일 안의 독립 해결 문항은 제외).
5. **바꾸지 않는 것.** 복습 간격 계산·`rules`·하루 5문제·`repeat_gap_days`·다시 연습·선수 경로와 진도 저장 계약은 그대로다. 졸업과 자리 수는 저장값이 아니라 기존 `streak`·`due`에서 계산하므로 기록 이전이 없고, 이미 `streak` 3 이상인 기록은 배포 직후 졸업으로 판단한다.

가상 비교(`python3 scripts/compare-engines.py --base 98809b6 --days 21 42 90`, 결과 [learning-paths-v2.3.json](experiments/learning-paths-v2.3.json), 2.2 대 2.3, Python):

- 모두 맞히는 학습자: 이미 본 문항 비율 21일 0.40→0.27, 42일 0.50→0.33. 90일 동안 4번 이상 나온 문항 40→0(SQL 53→0). 5문제를 못 채운 날 90일 동안 17→0. 단계 결과는 42·90일 같고 21일은 단계 1 개념이 없어졌다.
- 틀리거나 도움 받은 문항의 재도전 지연(기한 뒤 실제로 다시 나오기까지): 1/4 확률로 도움을 받는 학습자 42일 9.1→2.6일, 1/2 확률 학습자 7.3→1.6일, 단계 3을 처음 막히는 학습자 9.2→1.2일.
- 비용: 90일에는 새 문항이 바닥나 이미 본 문항 비율이 0.60→0.63으로 비슷하다(짧은 묶음 대신 복습으로 채운 묶음). SQL(53문항)은 새 문항이 일찍 바닥나 21일 비율이 0.44→0.50으로 오른다. 단계 3을 처음 막히는 학습자는 해결한 문항의 지연 복습이 밀려 42일 단계 3 개념이 12→7개로 늦지만 90일에는 11→14개다. 무작위로 자주 막히는 가상 학습자는 재도전이 제때 와서 SQL에서 4번 이상 나온 문항이 늘기도 한다(1/4 학습자 42일 17.8→23.3).

가상 이력이며 실제 학습 효과는 WBS-520/530에서 확인한다.

## 판단 과정 보관과 재현

새 묶음의 `session_started` 이벤트 detail과 세션의 추천 설명에 알고리즘 버전, 임계값, 선수 경로, 개념별 관찰 수·일수와 선택 이유를 저장한다. 기록은 기기/SQLite에 남고 외부로 자동 전송하지 않는다. 새 세션 화면은 해당 문제를 고른 이유를 간단히 표시한다. 이전 세션에 없던 근거를 만들어 넣지 않는다.

```bash
python3 scripts/simulate-learning.py --output docs/experiments/learning-paths-v2.json
```

이 실험은 가상 이력이다. 전처리·NumPy·SQL·pandas·통계의 기초 보충과 목표 문항 재도달, 웹/서버 일치를 확인한다. 실제 사용자 성과를 주장하지 않는다. 초기 독립 실험은 [v0.1 코드](experiments/adaptive-v0.1.py)와 [당시 입력 은행](experiments/problem-bank-v0.1.json), [실험 결과](experiments/adaptive-v0.1.json)로 보존한다. 운영 규칙은 위의 v2 단일 경로를 사용한다.

## 여러 업데이트 경로와 이후 개선

작업 시작과 게시 직전에 origin/main을 확인한다. 기존 ID·버전·snapshot을 보존하고 같은 ID의 다른 문제를 덮어쓰지 않는다. 원격이 앞서면 비강제 통합하고 영향받은 참조·추천·저장·모바일 검증을 다시 확인한다. 게시된 커밋의 Pages 성공과 공개 파일 일치로 배포를 확인한다.

실제 자료가 생기면 선수 문항을 거친 뒤의 변형 성공·힌트 재사용·지연 복습·불필요한 반복을 표본 수와 함께 검토한다. 경로와 임계값 변경은 버전·이유·반례·동일 이력의 전후 결과를 [개선 기록](CURRICULUM_LOG.md)과 프로젝트 관리 기록에 계속 추가한다.
