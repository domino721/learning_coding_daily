# 학습 기록 저장 안내

현재 사이트는 **같은 기기의 같은 브라우저**에 기록을 자동 저장합니다. 기존 `learning-coding-daily:v1` 키를 유지하면서 localStorage와 IndexedDB에 정상 저장본·이전 복구본을 보관합니다. 주 저장본이 누락되거나 손상되면 검증 가능한 복구본을 읽고 알려줍니다. 둘 다 읽지 못하면 빈 기록으로 초기화하지 않습니다.

## 기록과 화면

| 기록 | 보관/표시 |
| --- | --- |
| 전체 기간 누적 | 기본·추가·반복 연습의 완료 횟수. 오늘 목표가 새로 시작해도 유지 |
| 오늘 학습 | 한국 시간 기준 당일 기본·추가 완료 수. 날짜가 바뀌면 새 목표 시작 |
| 만난 문제 수 | 서로 다른 문제 수. 같은 문제 반복은 이 수를 늘리지 않음 |
| 날짜별 전체 풀이 | 지난 날짜의 기본·추가 묶음, 정답/해설 완료, 답안·해설·시도·힌트 |
| 활동 로그 | 학습 시작·제출·힌트·해설·완료·백업 병합. 이전 기록의 정확한 시각이 없으면 ‘시각 미상’ |
| 임시 답안 | 직접 입력 중 잠시 멈춘 뒤 자동 저장. 저장되지 않았으면 실패 안내 |
| 문항 원본 | 앱 업데이트 후에도 이미 시작한 묶음의 제목·코드·지문·형식·완료 내용 보존 |
| 학습 근거 | 독립 풀이·힌트·재시도·서술형 해설 비교·날짜를 구분한 개념별 추천 근거 |

정답으로 마침에는 재시도·힌트 후 정답도 포함됩니다. 이것을 첫 시도 정답률로 해석하지 않습니다. 개념별 추천은 첫 제출·힌트 없음·정답 완료·서술형이 아님을 모두 충족한 관찰을 사용하고 같은 날 반복으로 승급시키지 않습니다. 상세 기준은 [커리큘럼](CURRICULUM.md)에 있습니다.

기록을 읽을 수 있지만 저장 공간이 부족해 새 형식으로 쓰지 못한 경우에도 기존 기록 열람과 백업 다운로드는 가능합니다. 새로운 답안을 저장하지 못하면 완료로 처리하지 않습니다.

## 백업과 복구

‘나의 기록 → 백업 파일 내려받기’로 답안·로그·진도를 포함한 검증 파일을 보관합니다. 다른 기기나 브라우저에서는 ‘백업 파일 가져오기’로 파일을 확인한 뒤 합칩니다. 다른 학습 ID이면 본인의 기록인지 확인해야 합니다. 같은 파일을 반복해서 가져와도 풀이 수는 중복 계산하지 않습니다. 같은 ID의 완료 답안이 충돌하거나 파일이 손상/미지원 버전이면 기존 기록을 유지하고 가져오기를 중단합니다.

읽지 못한 저장본만 있을 때도 백업 복구 화면을 제공합니다. 적용을 명시적으로 확인한 경우 읽지 못한 원본은 별도 보관하고 검증된 파일로 복구합니다. 파일 제한은 10MB이며 정답·답안이 포함된 개인 파일이므로 본인 기록만 안전한 곳에 보관합니다.

**복구본도 같은 브라우저 안에 있습니다.** 브라우저 데이터 전체 삭제·기기 분실까지 막으려면 내려받은 파일을 기기 밖에도 보관해야 합니다. 계정 로그인과 기기 간 자동 동기화·외부 서버 백업은 아직 제공하지 않습니다. 저장 구조와 후속 서버 설계는 [기록 안정성 설계](RECORD_RELIABILITY.md)에 있습니다.

## 개발 서버 모드

SQLite `.data/learning.sqlite3`에 저장하며 v1/v2/v3→v4 이전 전에 `.schema-vN.backup`을 만듭니다. 웹 기록과 같은 백업 포맷으로 내보내기/가져오기를 지원합니다. 개인용 개발 서버이며 여러 베타 사용자에게 같은 단일 DB를 공유해서는 안 됩니다. 실제 Pages 기록은 이 서버로 자동 전송되지 않습니다.
