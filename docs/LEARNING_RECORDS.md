# 학습 기록 저장 안내

## 현재 휴대폰용 GitHub Pages 버전

기록은 **지금 접속한 기기의 해당 브라우저**에 저장한다. 브라우저의 `localStorage`를 사용하고 저장 키는 `learning-coding-daily:v1`이다. GitHub Pages는 앱 파일을 제공하며 학습 기록을 서버 DB나 GitHub 저장소에 업로드하지 않는다.

| 기록 | 실제 저장 내용 |
| --- | --- |
| 학습 묶음 | 날짜·기본/추가 묶음·문제 구성·완료 수·정답 완료 수 |
| 문제 결과 | 미완료/정답 완료/해설 완료·최근 제출 답·최근 정오답·시도 횟수·힌트 사용·누적 풀이 시간 |
| 제출 | 제출 ID별 문제·답안·정오답. 중복 제출 처리에도 사용 |
| 진도 | 문제별 완료 횟수·다음 복습 후보 날짜 |

오늘의 총 완료 수는 해당 날짜의 기본/추가 묶음 완료 수를 합산한다. 정답으로 마친 문제와 해설로 마친 문제를 모두 포함한다. 같은 문제를 추가 연습에서 다시 완료하면 오늘의 연습 횟수는 늘고, ‘지금까지 만난 문제’의 서로 다른 문제 수는 늘지 않는다.

홈의 **오늘 학습 돌아보기**와 완료 화면에는 오늘 마친 기본·추가 학습 전체의 문제와 해설을 표시한다. 미완료 문제는 제외하고, 같은 문제를 추가 연습에서 다시 마친 결과는 풀이별로 남긴다. 정답으로 마침·해설로 배움도 이 전체 목록을 합산한다.

정답률 백분율을 별도 값으로 저장하거나 종합 정답률 화면으로 제공하지는 않는다. 제출의 정오답과 문제의 최종 결과는 저장한다. 재시도 후 정답이나 힌트를 보고 맞힌 결과도 ‘정답으로 마침’에 포함하므로 이를 ‘첫 시도 정답률’로 해석해서는 안 된다. 해당 지표 정의와 학습 기록 모델 확장은 WBS-220 등 후속 설계 범위다.

같은 브라우저에서 일반적인 새로고침·앱 업데이트를 하면 기록을 다시 읽는다. 다른 기기·다른 브라우저에는 자동 공유되지 않는다. 사이트 데이터 삭제 시 기록이 지워지고, 시크릿 모드 기록은 브라우저 종료 후 유지되지 않을 수 있다. 현재 자동 서버 백업과 계정 동기화는 없다.

백업 내보내기/가져오기는 **WBS-270**, 계정·동기화는 **WBS-610~620**의 계획 항목이며 아직 제공되지 않는다. [WBS 현황](planning/WBS.md)에서 구현 여부를 확인한다.

## Python 서버 개발 모드

FastAPI 서버를 실행하는 개발 모드에서는 서버 파일 시스템의 `.data/learning.sqlite3`에 SQLite로 저장한다. `APP_DB_PATH`로 경로를 바꿀 수 있다. 세션·문제 상태·제출·진도 테이블을 사용한다. 서버 DB는 현재 휴대폰 GitHub Pages의 브라우저 기록과 별개이며 자동 연결되지 않는다.

구현 근거: [브라우저 저장](../src/browserApi.ts), [타입](../src/api.ts), [서버 집계](../backend/main.py), [SQLite 스키마](../backend/storage.py).

## 풀이 모드와 서술형 기록

새 학습 기본은 단답형이며 객관식·서술형으로 바꿀 수 있습니다. 모드 변경은 현재 묶음의 미완료 문제에 적용하며, 완료한 문제의 모드와 답안은 유지합니다. 객관식/단답형은 정답을 확인하고 서술형은 답과 이유(최대 2,000자)를 저장한 뒤 해설과 비교합니다. 서술형을 자동으로 정답·오답 판정하지 않으며 완료 결과는 ‘해설로 배움’에 포함합니다. 다음날 복습 후보가 됩니다. 작성한 서술 답안은 완료 화면의 해설에서 다시 확인할 수 있습니다.

SQLite v3는 v1/v2의 세션·답안·복습 진도를 보존하고 풀이 모드만 추가합니다. 기존 브라우저 기록의 완료 항목은 그대로 보존하며 새 모드 항목이 없는 문제는 기존 객관식/빈칸 방식을 이어갑니다.
