# 실제 휴대폰 7일 관찰과 품질 검토

이 문서는 사용 관찰을 실행하는 절차다. 개발 테스트·가상 이력을 실제 사용자 자료로 바꾸지 않는다.

1. 실제 휴대폰의 기존 사이트에서 ‘나의 기록 → 학습 품질과 7일 관찰 → 오늘부터 7일 관찰 시작’을 누른다. 기기·브라우저와 기존 기록 여부를 메모한다.
2. 매일 원하는 트랙의 기본 목표와 필요한 추가 학습을 한다. 일부러 정답을 외우거나 테스트 답안을 입력하지 않는다.
3. 막힌 문제·힌트·너무 쉬움/어려움·지루함·저장/화면 문제를 ‘오늘 사용 후기’에 남긴다. 실제 기기 확인은 본인이 체크한다.
4. 첫날과7일째에 백업 파일을 내려받아 별도로 보관한다. 새 브라우저에서 파일 복원을 시험하되 기존 브라우저를 지우지 않는다.
5. 7일 후 ‘관찰 지표 내려받기’와 사용 후기를 함께 검토한다. 개인 기록을 외부로 자동 전송하지 않는다. 제출은 사용자의 선택이다.
6. 베타 테스터가 백업 파일을 보내 주면 운영자는 주 1회 `python3 -I scripts/analyze-backups.py 파일...`로 문항별 정답률·독립 정답·힌트 후 성공·중앙값 시간을 집계한다. 결과는 문항 집계만 담고 개인 식별 정보와 답안 원문을 포함하지 않으며, 파일 자체는 저장소에 넣지 않는다. 검토 후보는 다음 주 정비 대상(`docs/CONTENT_AUTOMATION.md`)에 반영한다.
7. 문항 오류·불편은 해설 화면의 ‘이 문제 신고 내용 복사’로 문항 ID·버전·배포본을 복사해 운영자에게 메신저로 보낸다. 앱 상단의 배포본 표시(날짜 commit)로 어떤 배포본에서 난 후기인지 구분한다.

## 지표의 분모

- 독립 정답: 완료 문항 중 첫 시도 정답·힌트0·서술형 아님. 같은 문항의 날짜별 풀이도 관찰 횟수로 나타내되 추천의 서로 다른 문항 수와 구분한다.
- 도움 후 정답: 정답 중 힌트 또는 재시도가 있는 결과.
- 힌트 후 성공: 힌트를 사용한 모든 제시 문항이 분모다. 미완료도 분모에 남는다.
- 지연 복습: 같은 ID·버전의 과거 다른 날 완료가 있는 review 문항. 다른 새 문항을 다음날 처음 푼 것은 지연 복습이 아니다.
- 다른 유형: 같은 개념의 과거 다른 날 독립 풀이와 현재 문항 유형군이 다른, 단계2 이상 완료 문항. 편집 분류에 의존하며 학습 전이를 확정하지 않는다.
- 활성 시간: 완료 결과의0초 초과 표본.0초/미측정은 따로 표시하고 중앙값에 섞지 않는다. 제출 없는 종료는 누락될 수 있다.
- 중단: 과거 날짜의 미완료 묶음과 명시적 뒤로가기 pause 이벤트를 구분한다. 누락된 시간·의도·브라우저 강제 종료는 추측하지 않는다.
- D1/D7: 최초 완료일의1일/7일 뒤 정확한 날짜에 완료가 있는지 확인한다. 아직 그날이 되지 않았으면 관찰 대기다. 이 기기의 개인 기록이며 전체 사용자 유지율이 아니다.

## WBS-530 검토 산출물

기기·실제 관찰 날짜·표본·누락을 먼저 적는다. 문제별 독립 정답, 힌트 후 성공,3분 초과와 자유 의견을 보고 각 문항을 유지/개선/보류로 분류한다. 이유와 구체적인 코드·보기·힌트 변경 후보를 기록한다. 하나의 오답만으로 자동 난이도 변경을 결정하지 않는다.

특히 기초를 거친 뒤 다른 유형 성공, 다음날/지연 복습, 불필요한 반복, 후보 소진을 확인한다. 개인 표본으로 통계적 효과를 입증하지 않는다. 추천 임계값 변경은 새 알고리즘 버전·반례·동일 이력의 전후 비교·CR을 남긴다.

실제7일 자료가 없으면 WBS-520/530은 미완료다. UI와 검증 도구 제공, 실제 기기 관찰 완료, 품질 판단 완료를 각각 구분한다.
