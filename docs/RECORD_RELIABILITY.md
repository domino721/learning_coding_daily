# 베타 학습 기록 보존과 복구

## 현재 제공하는 보장

현재 사이트의 주소와 origin은 `https://domino721.github.io/learning_coding_daily/`로 유지한다. 기존 `learning-coding-daily:v1` 키도 유지한다. 외부 서버로 개인 답안/로그를 전송하지 않는다.

1. 기존 저장본을 정상적으로 읽었으나 이전 형식으로 쓸 저장 공간이 없으면 읽기/파일 백업은 허용하고 저장 제한을 안내한다. 저장 성공을 확인한 뒤에만 답 확인/완료를 화면에 반영한다. 두 저장소 모두 쓰기에 실패하면 해당 문제를 미완료로 유지하고 다시 시도할 수 있다.
2. 기존 localStorage 저장본과 IndexedDB 저장본을 함께 보관하고 각 이전 저장본도 남긴다. 주 저장본이 누락/손상되면 검증 가능한 최신 복구본을 읽는다. 정상 복구본이 없으면 오류를 보이며 새 빈 기록으로 덮어쓰지 않는다.
3. 버전·구조·합계를 검증한다. 미래 버전의 주 저장본을 오래된 복구본으로 자동 덮어쓰지 않는다. 복구 적용 시 읽지 못한 원본은 별도로 보관한다.
4. 세션·문제·제출 ID, 완료 상태, 이전 문항 원본, 답안, 힌트, 시도 횟수와 로그를 보존한다. 미완료 문제의 입력도 잠시 멈춘 뒤 자동 저장한다. 이전 버전의 정확한 시각이 없는 완료 로그는 ‘시각 미상’으로 표시한다.
5. 화면은 오늘 완료 수·전체 기간 누적 풀이 수·서로 다른 문제 수를 구분한다. ‘나의 기록’에서 이전 날짜까지 열람하고 백업 파일을 내려받거나 가져온다.
6. 파일 백업은 SHA-256 검증 값과 포맷/데이터 버전을 포함한다. 적용 전 요약을 보이고 다른 학습 ID일 때 본인 확인을 요구한다. 같은 ID는 중복 계산하지 않고 완료된 답안을 미완료 기록으로 되돌리지 않는다. 완료 답안 충돌/손상/미지원 버전이면 가져오기를 중단하고 기존 기록을 유지한다.
7. 같은 날짜의 다른 기기 묶음 번호가 겹치면 ID는 보존하고 뒤쪽 추가 묶음 번호를 배정한다. 원본 파일은 유지해야 한다.

## 보장의 한계

두 저장소는 모두 같은 기기·브라우저에 있다. 브라우저 데이터 전체 삭제, 기기 분실, 브라우저의 origin 전체 정리까지 막는 외부 백업은 아니다. 정기적으로 내려받은 파일을 기기 밖의 안전한 곳에도 보관해야 한다. 다운로드 버튼은 파일 저장을 요청하며 운영체제에서 실제 보관을 완료했는지까지 앱이 보증하지 않는다.

같은 기기·같은 브라우저에서 업데이트 후 리셋된 것처럼 보였다는 보고가 있었다. 개인 기기의 저장값을 직접 열람할 수 없어 원인은 확정하지 못했다. 기존 코드는 오늘/최근 7일 중심이라 날짜 전환이 혼동을 줄 수 있었고, 주 저장본만 사용해 브라우저 저장 실패/삭제 시 복구 경로가 부족했다. 기존 저장값이 남아 있으면 그대로 이전하며, 이전에 실제로 지워지고 백업도 없는 데이터는 임의로 재구성하지 않는다.

SQLite 개발 모드는 v1/v2/v3 파일을 v4로 이전하기 전에 `.schema-vN.backup`을 만든다. 기존 제출과 진도를 보존하며 문항 snapshot·활동 로그·임시 답안·독립 복습 간격을 추가한다. 개발용 서버는 개인용이며 여러 베타 사용자를 이 단일 DB에 연결해서는 안 된다.

## 후속 서버 저장 설계

기기 분실/브라우저 전체 삭제에도 복구하고 기기 간 자동 동기화하려면 별도 인증·저장 서버가 필요하다. 현재 GitHub Pages는 정적 파일만 제공한다. 외부 계정/서비스가 정해지지 않은 상태에서 ‘클라우드에 안전하게 저장된다’고 표시하지 않는다.

최소 후속 구조는 다음과 같다.

- 서버가 발급한 사용자 ID와 로그인/복구 수단, 사용자별 읽기/쓰기 권한을 둔다. 브라우저의 표시용 학습 ID만으로 다른 사람의 기록을 조회하지 못하게 한다.
- 사용자별 세션 snapshot과 append-only 이벤트, 제출 UUID에 유일 제약을 두고 중복 재전송을 처리한다. 서버가 수신한 revision/확인 시각을 클라이언트에 돌려준다.
- 브라우저는 확인받지 못한 이벤트를 보관하는 outbox와 재시도, 충돌 시 완료 기록 보존 규칙을 유지한다. ‘기기 저장됨’과 ‘서버 동기화됨’을 구분한다.
- 자동 DB 백업과 실제 복원 연습, 사용자 파일 내보내기/삭제 정책, 비용·보존 기간을 정한다. 기존 브라우저 기록 연결은 미리 요약을 보이고 본인 확인 후 수행한다.
- Pages 주소는 유지하고 인증 API만 연결하는 구성이 가능하다. 호스팅 이전이 필요하면 기존 origin에서 먼저 파일 백업과 이전 UI를 제공한다.

계정/서비스 선택과 접근 권한·비용은 WBS-610~620에서 확정한다. 이번 변경은 기기 내 복구·파일 백업·이전 검증을 제공하며 계정 서버를 배포하지 않는다.
