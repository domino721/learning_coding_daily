# EV-074 — 터미널·Git 트랙 분리와 Windows 섹터 로컬 검증

2026-10-30 Asia/Seoul / WBS-393·CR-020 / 기준선 1.16.0. 로컬 checkout(origin/main 63695a8 위 작업 트리) 검증이며 원격 저장·Pages 게시 전이다.

## 트랙과 문항

- 트랙은 다섯이다.
  - 터미널(`terminal-git`, domain 터미널, 50문항): 하루 사이 생긴 세션과 저장한 트랙 선택이 이어지도록 CR-019 ID를 유지한다.
  - Git(`git`, domain Git, 26문항): 새 트랙이다.
- 트랙 판정과 개념 선수 외의 선택 규칙·rules·review는 바뀌지 않았다.
- 새 ID 15개.
  - Windows 경로와 이동 4, PowerShell로 파일 다루기 4, Windows 환경 변수와 실행 4.
  - Windows에서 Python 실행 1(sh-windows-05, 한국어 Windows의 cp949 기본 인코딩).
  - Git 기초 2(git-status-05 .git 폴더, git-diff-05 diff 머리글·문맥 줄).
- 저장소와 상태·바뀐 내용(diff) 읽기의 선수 개념을 비워 Git 트랙이 터미널 트랙 없이 시작된다.
- 카드의 트랙·선수가 바뀐 Git 24문항은 version 2다. 학습자에게 보이는 내용은 git-status-02 해설의 echo 설명 한 문장만 더해졌다.
- 터미널 37문항과 다른 트랙의 (id, version)·경로·카드는 바뀌지 않았고, 2026-10-29 검수 기록도 그대로다.

## 검증

- Git 2문항은 `scripts/validate_shell_content.py`가 화면에 보인 시작 상태에서 bash·Git으로 실행해 정답과 보기를 대조한다. 웹 내보내기와 `tests/test_curriculum.py`·`tests/test_format_content.py`가 같은 실행을 반복한다.
- Windows 13문항은 Windows PowerShell 5.1·cmd·Windows Python 동작이라 macOS·Linux 검사에서 실행할 수 없다.
  - 다음 문서를 직접 열어 사실을 확인했다: Microsoft Learn(about_Pipeline_Chain_Operators, about_Character_Encoding, about_Command_Precedence, about_Environment_Variables, about_Path_Syntax, about_Parsing, Get-Location, Get-ChildItem, Remove-Item, Copy-Item, Get-Content, New-Item, cmd의 cd·pushd·set), Python 문서(Windows에서 사용하기, open), PEP 686.
  - 검수 기록 `curriculum/reviews/2026-10-30-windows-git.json`에 항목별 `sources`와 `basis`(verify: documented)를 남겼다.
  - 테스트는 documented 항목에 출처·근거가 있는지 확인한다.
- 생성 스크립트는 이미 게시된 문항의 보기 순서·정답·오답 근거를 origin/main에서 읽어 고정하고 새 문항만 섞는다. 정답 위치는 단일 정답 1·1·2·2, 모두 고르기 보기 3·2·2·3·2다.
- 정답을 모르는 별도 검수 에이전트가 새 15문항을 실행 없이 풀어 정답표와 15/15 일치했다(신뢰도 낮음 0). 풀이 뒤 해설의 사실을 공식 문서로 다시 확인했다.
  - 정답이 드러나던 지문 2개(win-path-03, win-env-03)를 고쳤다.
  - 사실 오류 3건을 고쳤다: PowerShell의 set은 환경 변수를 만들지 않음, &&를 ;로 바꾸면 뜻이 달라지고 Activate.ps1은 실행 정책에 막힐 수 있음, cp949 오류는 읽는 5번 줄에서 남.
  - 힌트·표현 지적을 고쳤다. 반영 내역은 검수 기록의 `independent_review`에 있다.
- 품질 게이트를 통과했다(단계 3 비출력 형식·코드 5줄 이상·오답 보기 강도 2 이상·보기별 오개념·검수 기록당 출력 예측 50% 이하). 새 검수 기록의 출력 예측은 39개 중 16개다.
- 홈(320×740)에서 트랙 카드 5장이 한 줄(카드 폭 53px, 넘침 없음)에 들어간다. Python 데이터 분석·터미널·Git 어느 트랙을 골라도 시작 버튼 아래끝(655px)이 하단 메뉴(664px)보다 위다. 두 새 트랙 설명은 Python 설명(224px)보다 짧다(214·202px).
- 같은 엔진의 가상 재생:
  - 터미널 첫날은 sh-path-01·sh-words-01·sh-path-03·sh-words-02·sh-path-02이고 Windows 문항은 2일째부터 섞인다. 모두 맞히는 학습자는 14일 안에 50문항을 보고 18일째 12개 개념이 단계 3이다.
  - Git 첫날은 git-status-02·git-diff-01·git-status-01·git-diff-05·git-status-05다. 모두 맞히는 학습자는 8일 안에 26문항을 보고 10일째 6개 개념이 단계 3이다.
  - 60일 재생 테스트에서 다섯 트랙의 개념이 모두 단계 3에 이른다.
- 보존: 바뀌지 않은 (id, version)·경로·카드·개념 50개와 순서·rules·review·origin/key·기록 계약을 지켰다. 단일 롤링 스냅샷은 389개다.

## 범위와 한계

- Windows 문항의 정답은 실행이 아니라 공식 문서 근거다. 한국어 Windows의 오류 문구는 문서로 확인하지 못해 지문에 영어 원문과 뜻을 함께 적었다.
- 가상 이력과 검수자 재풀이는 실제 학습 효과가 아니다. Windows 사용자의 체감과 정답률은 WBS-520/530에서 확인한다.
