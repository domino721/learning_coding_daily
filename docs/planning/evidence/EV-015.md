## 변경과 완료 조건 대조

- 활성 추천은 Python 데이터 분석 45개/SQL 10개. 원본 60개·난이도 정보·서술형 5개는 삭제하지 않는다. 두 트랙의 문항/선행 개념은 분리되어 Python 정답이 SQL 수준을 올리지 않는다.
- 콘텐츠 ID와 동일 domain/prompt/code 중복을 원본 로드에서 검사한다. 추천기는 기본/추가/이전 통합 묶음의 당일 할당 ID를 모두 제외하며 예정일 전 반복으로 채우지 않는다. 1~4개 후보는 실제 개수, 0개는 안내와 422로 빈 세션 생성을 막는다.
- 객관식 첫 오답은 pending, 두 번째 오답은 incorrect 완료·정답/해설·다음날 복습이다. 정답/오답/해설 확인/미채점을 화면과 기록에서 구분한다. 같은 UUID 재제출은 시도·진도·이벤트를 늘리지 않는다. 새 결과도 백업/병합 왕복한다.
- 기존 pandas 통합 세션·snapshot·답안·힌트·시도·이벤트·누적 횟수는 재분류/삭제하지 않는다. 비서술형만 이어하기, 서술형은 pending 상태와 임시 답안까지 보존하고 ‘보류·미채점’으로 열람/백업한다. 신규 서술형 생성/모드 지정/제출은 중단한다. 원래 완료 결과는 소급 변경하지 않는다.
- 트랙별 기본/추가 상태와 전체 트랙/이전 통합 누적·오늘 합계를 구분한다. 완료한 이전 통합 목표가 있을 때에도 기록 보존 및 새 트랙 목표 분리 안내를 표시한다. 기존 origin/key·복구본·읽기 전용 백업 경로를 유지한다.
