# EV-011 — 베타 학습 기록 보존·복구·파일 백업

대상: WBS-220·270, REQ-007·008·009·010·015. 2026-10-16, Asia/Seoul.

같은 기기/브라우저에서 업데이트 후 리셋된 느낌이라는 보고를 반영했다. 실제 기기 저장값은 열람하지 못했으므로 유실 원인은 확정하지 않는다. 기존 주소/origin과 `learning-coding-daily:v1` 키를 유지하며, 읽기 실패 시 빈 기록을 덮어쓰지 않는다.

- localStorage·IndexedDB의 정상/이전 저장본을 검증해 읽고, 누락/손상 시 복구본을 사용한다. 적어도 한 저장소의 쓰기 성공 확인 후만 UI를 완료로 바꾼다. 두 저장소 실패 시 미완료와 입력을 유지한다.
- 세션/문제/제출 ID, 기존 완료/미완료 snapshot, 답안, 힌트, 시도 횟수와 활동 로그를 보존한다. 직접 입력을 잠시 멈추면 임시 답안을 저장한다. 이전 기록에 없는 시각은 ‘시각 미상’으로 명시한다.
- SQLite v1/v2/v3→v4 이전 전에 원본 백업 파일을 만들며, 이전의 제출·진도·외래키 무결성·묶음을 보존한다. schema v3 백업 파일의 버전/제출 수도 직접 검증한다.
- SHA-256 검증 값이 있는 포맷 파일의 요약·학습 ID를 확인한 뒤 병합한다. 중복 제출/묶음은 늘리지 않으며 완료 기록을 미완료로 되돌리지 않는다. 부분 진도의 시도·힌트·활성 시간도 보존하고 서로 다른 임시/완료 답안 충돌은 적용을 중단한다.
- 손상·미지원 버전·구조/합계 불일치·잘못된 문항 snapshot/ID를 거절하며 실패 시 기존 데이터를 유지한다. 읽지 못한 원본만 있을 때 명시적 파일 복구를 허용하고 손상 원본은 별도 보관한다.
- 화면은 오늘 완료 수·전체 기간 누적 풀이 수·서로 다른 문제 수·이전 날짜의 답안/해설/로그를 구분한다. 한국 시간 자정에는 오늘 목표만 새로 시작하고 누적 기록은 유지되는지 검증했다.

pytest/Node와 모바일의 실제 실패 주입·복구 검증은 EV-012에 연결한다. 기기 내부 복구본은 브라우저 데이터 전체 삭제/기기 분실을 보장하지 않으며 파일의 기기 밖 보관이 필요하다. 계정/서버 동기화는 구현하지 않았다. `docs/RECORD_RELIABILITY.md`에 현재 보장·한계·후속 사용자별 서버/outbox/백업 구조를 분리했다. 이전에 실제로 삭제되어 저장본도 파일도 없는 기록을 복원했다고 주장하지 않는다.
