# EV-076: 일일 정비 결과를 기계적으로 다시 확인하는 검사 스크립트

2026-10-30 Asia/Seoul / WBS-370 / 기준선 1.16.0 유지.
- 기준: main 4d92101
- 검증 대상: 004f21a (브랜치 `wbs-370-maintenance-diff`, PR로 검토)

## 근거가 된 관찰

10월 30일 배치와 같은 기준 커밋(f226b71)과 같은 대상 다섯 건으로 로컬 Codex 대조 실행을 돌렸다.
- 이 실행은 저장소 밖의 일회용 복제본에서 했고, push하지 않았다.
- 대조 실행의 원자료는 이 저장소에 넣지 않았다.

관찰은 다음과 같다.
- **순서 변경:** 스크립트 없이 돈 기준 실행은 `curriculum/problem_bank.json`의 `coverage`에 내용은 같고 순서만 바뀐 변경을 남겼다. 스크립트와 실행 지시가 있는 실행에서도 같은 변경이 생겼지만, 스크립트가 `FLAG top-level "coverage" reordered only`로 표시했고 실행이 그 변경을 되돌렸다. 대조 실행이 1회뿐이라 효과의 크기는 아직 모른다.
- **손으로 짠 비교:** 기준 실행이 직접 짠 비교 코드는 한 번 실패했다. tuple과 list 차이 때문에 바뀐 문항이 34개 넘게 잡혔고, 고쳐서 다시 실행해야 했다.
- **문구 결함:** 10월 30일 클라우드 결과(63695a8)의 편집 필드에 숫자 앞 띄어쓰기가 빠진 문구가 3곳 있다. 스크립트의 ‘한글 바로 뒤 숫자’ 규칙에 해당한다.
  - `stats-median-01`: ‘합110을5로’
  - `pandas-group-03`: ‘기준을1건’
  - `numpy-shape-02`: ‘있는3축’

  모두 학습자가 보지 않는 필드다. 이 세 곳은 `docs/CONTENT_QUALITY_REVIEW.md`의 우선 정비 목록에 올렸다.

## 변경

- `scripts/maintenance_diff.py`
  - 읽기 전용이고 표준 라이브러리만 쓴다.
  - 작업 트리의 `curriculum/problem_bank.json`을 기준 ref와 비교해서, 바뀐 ID·필드·version 차이를 출력한다.
  - 다음 경우에 `FLAG`를 붙인다: 대상 밖 변경, version 없이 바뀐 학습자 필드, 학습자 변경 없이 오른 version, 변경이 없는 대상, 순서만 바뀐 최상위 키, 한자·가나 혼입, 한글 바로 뒤 숫자.
- `docs/CONTENT_AUTOMATION.md`
  - 4단계: 스크립트를 실행하고, `FLAG`마다 고치거나 근거를 남긴다.
  - 2단계: 우선 정비 목록을 먼저 처리한다.
- `tests/test_maintenance_diff.py`: 합성 문항 은행으로 표시 규칙과 무표시 경우를 검사한다.

## 검증

- `uv run --frozen pytest tests/test_maintenance_diff.py`: 2 passed.
- 같은 작업 트리에서 `bash scripts/check.sh`를 실행했다. 결과는 작업 기록 LOG-107에 적는다.

## 한계

- 클라우드 일일 배치에 미치는 효과는 머지 뒤 실제 배치 결과로 확인해야 한다.
- ‘한글 바로 뒤 숫자’ 규칙은 정상 표기(예: 서수 접두어 뒤 숫자)도 표시할 수 있다. 계약은 이런 경우 고치는 대신 한 줄 근거로 넘기게 한다.
- 모바일 E2E는 이번 변경과 무관해서 다시 돌리지 않았다.
