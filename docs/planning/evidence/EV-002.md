# EV-002 — 설계/WBS 관리 체계 검증

대상: WBS-110, CR-004. 기준일 2026-10-15, Asia/Seoul.

## 실행 결과

- `python3 scripts/planning.py check`: 설계/계획 1.0.0, 작업 28건의 참조·기준선 해시·의존성·완료 근거·생성 문서 일치 검사 통과.
- `python3 -m unittest discover -s tests -p test_planning.py`: 10개 통과. 정상 자료, 기준선 해시 불일치, 순환 의존성, 근거 없는 완료, 오래된 생성 문서, 없는 선행 ID, 버전 참조 불일치, 해시를 다시 계산한 과거 기준선 덮어쓰기, 작업 로그 없는 코드 변경, 적용된 CR 수정 사례를 검증했다.
- `bash scripts/check.sh`: 관리 검사, 콘텐츠 내보내기 일치, 코드 형식, TypeScript 검사/프로덕션 빌드, pytest 52개 통과. 52개는 기존 서버·콘텐츠 42개와 관리 도구 10개다.
- `npm run test:e2e`: 모바일 E2E 6개 통과. 브라우저 단독 모드와 서버 모드에서 다섯 분야 학습·힌트/해설 흐름·저장/복구·오류 복구를 확인하고, 기존 완료 기록 이전과 추가 학습 경로를 확인했다.

## 산출물과 적용 범위

설계와 계획의 버전 원장, 원문 보존, 28개 WBS의 산출물/의존성/담당/상대 규모/완료 조건, 변경/작업/결정/위험/검증 기록, 루트 AGENTS 지침, 관리 검사와 CI 연결을 구성했다. 관리 검사를 Pages 게시 단계에도 연결했다. 앱 기능이나 저장 형식은 이번 변경에서 바꾸지 않았다.

이번 기준선 채택 commit을 `design-v1.0.0`, `plan-v1.0.0` annotated tag로 식별한다. 원격 실행 결과는 별도 관찰 사항이며 이 로컬 검증 기록에 소급 포함하지 않는다.

## 한계

자동 검사는 자료의 구조·이력·선언된 근거를 확인하며 설계 내용의 타당성이나 학습 효과를 대신 판정하지 않는다. 실제 휴대폰 사용, 학습 소요 시간, 개인화 효과는 후속 WBS에서 검증한다. 원격 브랜치 보호나 독립 QA 인력이 구성되었다고 주장하지 않는다.

검사 중 기존 FastAPI/Starlette TestClient의 httpx 사용 중단 예고와 Node 색상 환경 경고가 있었으며 실패는 없었다.
