## 학습 흐름과 콘텐츠

오늘의 기본 학습 → 선택·빈칸 문제 → 요청형 힌트/오답 재시도 → 정답 또는 해설 학습 → 결과. 기본 완료 후 추가로 5문제씩 계속 풀 수 있다. 추가 묶음은 안 푼 문제를 우선하고, 모두 풀면 가장 오래전에 만난 문제부터 연습한다. 기본 결과를 덮어쓰거나 기존 기록을 지우지 않는다.

목표·입력·출력·필수 조건은 명확하게 주되 연산을 지문에서 대신 해석하지 않는다. `axis=0/1`, Series/DataFrame, NULL, 조인 행 수, 분모, fit/transform처럼 실제 오개념을 확인한다. 풀이 방법·개념은 요청형 힌트나 학습 완료 후 해설에서 제공한다. 구체적인 검수 기준은 [콘텐츠 지침](../../CONTENT_GUIDELINES.md)을 따른다.

전체 범위는 Python 데이터 다루기, NumPy 배열·축·벡터화, pandas 정리·집계·조인·시간, SQL 조건·집계·조인·CTE·윈도 함수, 통계·추정·검정·실험·인과 해석, scikit-learn 전처리·Pipeline·검증·지표·모델링, EDA·matplotlib/seaborn 시각화·의사결정이다. 현재 30문제로 이 전체 범위가 완성되었다고 주장하지 않는다.

## 적응형 학습의 확정 원칙과 미확정 매개변수

개념별 실력과 선행 조건을 사용하고, 한 번의 정답만으로 숙련 처리하지 않는다. 서로 다른 문제의 독립 정답과 이후 복습 성공을 구분한다. 힌트·해설·재시도·같은 날 반복을 고려한다. 느리게 풀었다는 이유만으로 실력을 낮추지 않는다. 추가 학습은 자율 선택이며 벌칙·의무 분량을 만들지 않는다.

진단 길이, 숙련 상태 전이의 수치, 승급/회귀 기준, 복습 간격 조정 방식은 아직 구현·실측으로 확정되지 않았다. WBS-210~250에서 규칙·경계 사례·결정 근거를 먼저 기록한 뒤 구현한다. 이를 이미 동작하는 맞춤 추천으로 표시하지 않는다.

## 기술·데이터 계약

React·TypeScript·Vite 모바일 웹을 유지한다. 무료 `web` 빌드는 GitHub Pages에서 실행하고 학습 기록을 해당 기기의 브라우저에 저장한다. Python 3.12·FastAPI·SQLite 개발 모드도 유지하며 문제 원본은 `backend/content.py`, 웹 콘텐츠는 JSON 내보내기로 일치시킨다. 두 모드의 공통 학습 동작은 같은 검증 시나리오를 통과해야 한다.

브라우저 저장 버전은 1, SQLite 스키마는 2다. 데이터 분석 트랙 내부 ID `pandas`는 이전 진도와의 호환 때문에 유지한다. 문구 개선은 완료 기록을 보존하고 미완료 카드에만 적용한다. 채점 의미나 정답을 바꾸면 새 문제 ID를 사용한다. 새로운 데이터 구조에는 이전 버전 fixture와 복구 검증이 필요하다.

직접 코드 작성은 Worker/격리 실행 PoC에서 모바일 호환성·시간/출력 한도·중단/재시작·오류 피드백을 검증한 후 도입한다. 실행이 실패하거나 기능을 지원하지 못하면 한계를 기록하고 정적 문제로 안전하게 유지한다. API 내 eval/exec·단순 subprocess 채점은 채택하지 않는다. 저장소가 작성한 예제의 개발 테스트는 사용자 코드 실행과 구분한다.

## 1.3.0 변경 — CR-007 (이전 규칙보다 우선)

REQ-016: Python 데이터 분석(pandas·NumPy·통계·scikit-learn)과 SQL은 독립 트랙 python/sql이다. 기존 pandas ID 통합 묶음은 그대로 남기고 누적/날짜별 기록에 포함한다. 개념별 근거만 공유하므로 Python 성적이 SQL 선행 조건/승급을 채우지 않는다.

신규 추천은 객관식·단답형만 제공한다. 서술형 원본/기록/임시 답안은 보존하되 이전 서술형 미완료 문항은 보류하고 자동 오답 처리하지 않는다. 객관식은 최대 두 번, 두 번째 오답은 incorrect 완료·정답/해설 공개·다음날 복습이다. 중복 제출 ID는 기회를 더 쓰지 않는다. 기존 완료 결과는 소급 변경하지 않는다.

기본·추가·이전 통합 묶음까지 같은 날 이미 제시한 ID는 추천하지 않는다. 신규/기한 도래 복습만 선정하고 반복 채우기를 중단한다. 후보가 다섯 개 미만이면 실제 개수로 시작하며 0개면 빈 세션을 만들지 않고 소진을 안내한다. 기본 다섯 문제는 목표이며 상한이 아니다. 서로 다른 ID지만 지문/코드가 동일한 콘텐츠도 원본 검사로 방지한다.
