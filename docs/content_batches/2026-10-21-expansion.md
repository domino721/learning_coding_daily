# 2026-10-21 API 의미와 입력 검증의 학습 경로 보강

WBS-360·WBS-540, REQ-005·007·012·013·019·020의 기존 유지보수다. 사용자가 커리큘럼·난이도·구조 보존, 고품질 문제 추가와 배포, Python의 where·isin·isfinite·isinstance를 요청했다. 기준 소스는 원격 main `2c5bc52eee37c48190c77cad5ecf878cba45bc1a`다. 기존 where와 pandas isin은 각각 한 문항에 등장했지만, isfinite·isinstance와 NumPy isin의 직접 연습은 없었다. 이는 문항 조사이며 사용자의 실제 오답이나 능력을 관찰한 근거는 아니다.

## 구성과 보존

기존 18개 개념 안에 Python 15개·SQL 3개를 추가한다. 기초·적용·전이는 각각 6개이며 객관식 11개·단답형 7개다. 새 단원, 화면, 추천·승급·복습 규칙이나 임계값을 만들지 않는다. 기존 159문항 전체 필드와 선수 경로, 설계 카드와 보류 초안은 해시로 보존한다. 서술형 5개는 계속 보류하며 총 보관 177개, 활성 Python 134개·SQL 38개다. 서울 날짜의 정기 5문항 배치는 변경하지 않는다.

자료형을 확인하는 기초는 기존 행·열 선택 경로에, 유한성 검사는 조건 마스크와 결측치 처리에 연결한다. 순수 Python 입력 검증 문항은 pandas 선택 전에 필요한 자료형 판단을 다룬다. 입력이 Python 기본 자료형임을 명시하여 NumPy 스칼라까지 같은 정책으로 인정한다고 오해하지 않게 한다. 보조 문법인 리스트 표현식은 지문에서 읽는 법만 안내하고 조건의 정답은 설명하지 않는다.

## 개별 검수와 선수 경로

앱 밖 초안을 Codex가 별도 재풀이한 뒤 실제 Python·NumPy·pandas·SQLite 출력 18개와 대조했다. SQL은 표시된 CREATE/INSERT 전체 입력만으로 재현한다. 단일 정답과 각 오답의 가설·진단, 힌트 2단계, 예상 시간과 난이도 근거, 보충 문항·다른 날의 변형 기준을 [개별 검수 기록](../../curriculum/reviews/2026-10-21-expansion.json)과 [설계 카드](../../curriculum/problem_bank.json)에 작성했다. 새 카드를 자동 승인하는 도구는 사용하지 않았다.

기초는 API 하나의 의미를 확인한다. 적용은 같은 개념의 기초를 요구하고, 전이는 같은 개념의 적용 단계와 필요한 API 기초를 연결한다. 예를 들어 타입 기초 → 숫자 입력 검증 → 결측/유한성 구분과 혼합 입력 검사, where 기초·기존 라벨 정렬 적용 → 대체 Series 추적, 포함 기초 → 원본 순서·중복 및 후보 Series 비교로 이어진다. 기존 운영의 충분한 개념 근거에 따른 선수 인정 정책도 보존한다.

90·120·180초와 난이도는 편집 추정이다. 실제 학습 효과·다른 날 변형 성공·힌트 재사용·지연 복습·시간 보정은 기존 WBS-520/530에서 별도로 관찰한다. 개인 학습 로그를 수집하거나 외부 모델 API를 호출하지 않았다.
