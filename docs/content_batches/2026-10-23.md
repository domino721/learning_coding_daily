## 참조 풀이와 별도 검수

원본 JSON의 code가 독립 실행 가능한 참조 풀이이며 SQL은 reference_setup을 먼저 실행한다. 입력 전체 CREATE/INSERT를 화면 코드에 표시한다. 초안은 앱 원본 밖에 작성하고 아래처럼 다시 푼 뒤 실제 라이브러리 출력을 대조했다.

1. B팀 누적은 2→5, A팀은 5→12다. 원래 B/A/B/A 위치로 놓으면 [2,5,5,12]. 전체 누적 [2,7,10,17], 최종합 반복 [5,12,5,12], 팀별 재정렬 [5,12,2,5]와 구별된다. 독립 사전 누적으로 빈 입력/한팀/교차팀/음수/0/사용자 인덱스를 대조하고 groupby sort 설정과 무관한 위치 보존·원본 불변을 확인했다. 이번 입력에 결측 그룹은 없으며 결측 키 동작으로 일반화하지 않는다.
2. 입력 두 개는 각각 shape (2,)다. stack은 새 길이2의 바깥 축을 만들어 (2,2), concatenate는 기존 축을 이어 (4,)가 된다. 원소 수만으로 축 수를 판단한 보기와 구별된다. 길이0/1/3과 2차원·빈축 입력의 실제 값/shape/총수·원본 불변을 대조했다. 다른 길이 입력에서 stack은 ValueError, concatenate는 연결 가능함도 확인했다. 임의 차원의 모든 axis 설정을 동일하게 일반화하지 않는다.
3. 질의점 (0,3)과 행0/1/2의 제곱거리는 9/18/1이다. 거리 순서의 학습 행 번호가 2→0이므로 [[2,0]]. 레이블 C/A, 입력 순서, 한 좌표만 비교한 결과가 다른 오답이다. 질의점·k=1/2/3, 학습 행의 모든 순열과 무관한 레이블 변경을 독립 제곱거리 정렬로 대조했다. 각 경계의 거리도 서로 달라 동점 정책을 가정하지 않는다. predict나 투표는 호출하지 않는다.
4. id 순서의 금액은 2/5/3이고 각 현재 행까지 합이 2/7/10이다. OVER가 원래 세 행을 보존하므로 전체 합 한 행 [10]이나 원래 금액 열이 아니다. 명시적 ROWS와 고유 id로 RANGE/동점 모호함을 피했다. 빈표/한행/역삽입/음수/0/처음·중간·전체 NULL에서 수동 누적을 SQLite와 대조했다. 윈도에 유효값이 아직 없으면 NULL이며 NULL을 0으로 치환한다고 설명하지 않는다.
5. 동점 보조키까지 정렬한 전체 id는 [2,3,1,4]. 첫 한 행을 건너뛴 뒤 최대 두 행은 [3,1]이다. OFFSET 무시, 삽입 첫 행 먼저 제거, id 값 기준 제외의 오답과 구별된다. 빈표/한행/동점/역삽입, OFFSET0/끝/초과, LIMIT0/남은 수 초과를 Python 정렬 후 슬라이스로 대조했다. 입력 id는 고유하고 amount는 비결측 정수이며 음수 LIMIT/OFFSET의 SQLite 특수 규칙을 일반화하지 않는다.
