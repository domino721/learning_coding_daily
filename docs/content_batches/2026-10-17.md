## 편집 검수와 오개념

제목은 상황을 나타내고 질문은 출력/답안 형식만 요구한다. 풀이 전 개념·힌트를 노출하지 않는다. SQL 입력 전체는 실행 코드의 주석으로 제시한다. 두 힌트는 확인 관점에서 개념 단서로 진행하며 정답 문자열을 그대로 제공하지 않는다.

- pandas: 위치 대입이면 0, 모든 라벨 불일치면 2, 즉시 오류라는 보기와 구별한다. 실제로 A만 누락되고 B는 10, C는 새 행을 만들지 않는다.
- NumPy: `[2, 6]`은 행 필터, `[99, 4, 99]`는 분기 반전, `[2, 4, 6]`은 원본 유지다. 위치별 선택은 길이 3을 보존한다.
- NOT EXISTS: NULL이 들어간 NOT IN의 결과 `[]`, EXISTS 반전 `[1]`, 조건 무시 `[1, 2, 3]`과 다르다. 중복 환불도 존재 여부를 바꾸지 않는다.
- 다중 조인: 원본 합 `(10, 10)` 및 한쪽 반복만 본 `(20, 10)`, 두 지표를 같은 값으로 본 `(40, 40)`과 다르다. 2×2 조합 네 행에서 각 필드를 따로 합산한다.
- 인코더: 학습된 두 열에 알려지지 않은 범주는 모두 0이다. 새 열 추가·재학습·기존 범주로의 임의 할당은 하지 않는다. ignore 설정을 빼면 새 범주에서 오류가 난다.

각 객관식/호환용 보기 네 개는 서로 다른 정답 의미를 갖는다. 실제 반환형과 출력 형식을 명시해 답을 유일하게 만든다. 난이도와 시간은 편집 추정값이며 사용자 실측 보정은 아직 하지 않았다.

## 부족분 선정과 참조 풀이

추가 전 활성 문항의 수준별 분포를 확인했다. pandas-select는 수준 1 두 개/수준 3 한 개로 수준 2가 비어 있었고, numpy-mask는 수준 2·3만 있어 수준 1을 보완했다. ml-preprocessing의 두 문항은 모두 StandardScaler여서 범주형 입력 변환을 추가했다. SQL은 행 조건의 NOT IN·COALESCE, 조인의 단일 LEFT JOIN과 달리 상관 NOT EXISTS와 두 상세 표의 다중 조인을 다룬다. 같은 숫자 교체나 동일 실행 패턴의 변형을 추가하지 않았다.

각 문제의 실행 가능한 참조 풀이는 원본 JSON의 `code`(SQL은 `reference_setup`을 먼저 실행)이며, 아래 독립 계산으로도 다시 풀었다.

1. pandas: 오른쪽 값을 이름별 사전 B→10, C→20으로 놓는다. 왼쪽 A/B 중 A만 사전에 없으므로 결측 수는 1이다.
2. NumPy: 첫째 True→2, 둘째 False→99, 셋째 True→6을 순서대로 놓아 `[2, 99, 6]`이다.
3. SQL 존재 검사: 고객 1만 환불의 비NULL ID 집합 {1}에 있다. 나머지를 정렬하면 `[2, 3]`이다.
4. SQL 다중 조인: 조합 (A,4), (A,6), (B,4), (B,6)에서 주문 금액은 10×4=40, 결제는 4+6+4+6=20이다.
5. 인코더: 학습 열 A/B 중 C가 해당하는 열이 없고 ignore 설정이므로 각 열 0, 행 하나를 포함해 `[[0, 0]]`이다.
