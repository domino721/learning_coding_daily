## 참조 풀이와 편집 재검수

원본 JSON의 code가 실행 가능한 참조 풀이이고 SQL은 reference_setup을 먼저 실행한다. 아래 독립 계산으로 다시 풀고 실제 출력과 대조했다.

1. 내림차순의 90 두 개는 위치1/2를 차지한다. min은 그중1을 함께 사용하며 80은 위치3이다. dense의 [1,1,2], first의 [1,2,3], 오름차순의 [2,2,1]은 모두 다르다. 다른 동점 위치·모두동점·음수·단일값은 더 큰 값의 개수+1과 대조했다. 지문에는 결측이 없으며 rank의 NaN 결과를 정수로 캐스팅할 수 있다고 일반화하지 않는다.
2. 각 행에서 뒤-앞을 계산하면 (5-2,9-5)=(3,4), (7-10,3-7)=(-3,-4)다. 원래3열에는 간격2개다. 행 사이 차이·반대방향 차이·원본유지가 다른 보기다. 단일행/단일열/1원소/음수/같은값에서 Python 인접쌍 계산과 shape를 확인했다. 지문은 부호 있는 정수이며 unsigned dtype의 뺄셈을 일반화하지 않는다.
3. 정렬값[0,2,6,8]의 linear 위치는 (n-1)q=0.75다. 왼쪽0에서 오른쪽2로75% 이동하면1.5다. lower=0, midpoint=1, nearest=2를 실제로 비교했다. 입력순서변경·q=0/1·모두같은값·단일값을 정렬+floor/ceil 보간과 대조했다. 방법을 생략하지 않아 분위수 정의의 모호함을 피한다.
4. A_%는 A 뒤에 최소1글자가 필요하다. AB/A_B는 맞고 A·B_A·NULL은 남지 않는다. 밑줄을 리터럴로 본[3], 0글자도 허용한[1,2,3], 시작위치를 무시한[2,3,4]와 다르다. 빈표/NULL/짧은이름/중복이름/뒤쪽0글자/긴이름과 ESCAPE로 밑줄을 리터럴로 찾는 반례를 확인했다. 입력은 대문자ASCII로 고정되어 SQLite의 대소문자 기본정책 차이를 답에 섞지 않는다.
5. USING(id)는 연결키를1번 내보내므로 왼쪽 id/amount 뒤 오른쪽의 비키 bonus가 남아 (1,10,7)이다. ON의4열·좌우순서반전·키전부제거와 다르다. 오른쪽중복/미일치/빈표/NULL키를 Python 동등조인과 대조하고 결과열이 id,amount,bonus인지 확인했다. 반대조인순서는 (1,7,10), ON은 (1,10,1,7)인 반례다. 지문은 한행이므로 결과행정렬의 모호함이 없다.
