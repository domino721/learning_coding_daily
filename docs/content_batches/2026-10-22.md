## 참조 풀이와 별도 재검수

원본 JSON의 code가 실행 가능한 참조 풀이이며 SQL은 reference_setup을 먼저 실행한다. 아래 독립 계산으로 다시 풀고 실제 출력과 대조했다.

1. 사전에서 A는1, B는None, C는미등록이다. 뒤의 두 경우가 결측이므로 [False,True,True]다. 키 존재만 본 경우, 미등록값 보존(replace 혼동), 행 이름으로 찾은 경우가 다른 오답이다. 모두등록/모두결측·빈입력·None 입력과 원본 불변, replace의 미등록C 보존을 확인했다.
2. 학습 최소0/최대10을 재사용하면20은 (20-0)/10=2다. clip=True만 결과를 기본 경계1로 자른다. 기본도 자동 제한, clip 무시, 원본 유지가 다른 오답이다. 범위 아래/양끝/중간/위의 -5/0/5/10/20을 수동 환산·clamp와 대조하고 transform 뒤 학습 극값이 변하지 않음을 확인했다. 입력은 비상수 학습 범위이며 상수열의 별도 동작을 일반화하지 않는다.
3. x의 중심화[-1,0,1]과 y의 중심화[10,0,-10]의 곱 합은 -20, 제곱합 곱의 제곱근은20이므로 계수는-1이다. 기울기-10·양의관계1·무관계0과 다르다. 양/음의 직선·상관0인 관측·쌍 순서 변경 및 양의 배율/평행이동을 Python 중심화 공식과 대조했다. 입력은 두 열 모두 변동이 있고 상수열에서 상관이 정의된다고 일반화하지 않는다.
4. SQLite의 IS는 (1,1)과 (NULL,NULL)을 모두 참으로 보며 한쪽 NULL은 다르므로 id1/2다. 일반 등식(=), NULL 전용 검사, NULL을 와일드카드로 본 오답과 다르다. 빈 표·같은정수·다른정수·양쪽/한쪽NULL·반복NULL을 수동 비교와 대조하고 =에서는 양쪽NULL도 남지 않음을 확인했다. SQLite의 INTEGER/NULL 입력으로 한정해 다른SQL 문법/자료형 비교를 섞지 않는다.
5. 같은 팀 쌍은 A팀의 (1,1)/(1,2)/(2,1)/(2,2), B팀의 (3,3)이다. 작은id가 왼쪽인 조건으로 (1,2)만 남긴다. 역순·자기쌍·다른팀 쌍이 오답이다. 빈표/한사람/모두같은팀/다른팀/NULL팀/입력id순서 변경에서 수동 이중순회로 순서 없는 쌍을 확인했다. NULL끼리는 ON 등식에서 연결되지 않는다. 지문 결과는 한행이어서 튜플이 유일하다.
