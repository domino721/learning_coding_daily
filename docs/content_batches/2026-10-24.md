## 참조 풀이와 별도 검수

원본 JSON의 code가 독립 실행 가능한 참조 풀이며 SQL은 reference_setup을 먼저 실행한다. 화면 코드에 전체 CREATE/INSERT 입력을 보인다. 초안을 앱 원본 밖에 작성한 뒤 다음 독립 계산으로 다시 풀고 실제 pandas/NumPy/scikit-learn/SQLite 출력과 대조했다.

1. 비교 대상 code의 A가 id1과3에서 반복된다. keep=False는 첫 A도 예외로 두지 않아 두 행 모두 True이므로 [1,3]. first 설정의 [3], last 설정의 [1], 유일 행의 [2,4]와 구별된다. Python 빈도표 및 앞/뒤 등장 여부로 빈표·유일값·두/세 중복·두 그룹·행 순서/사용자 인덱스와 원본 불변을 확인했다. 입력은 문자열이고 결측 중복의 자료형별 정책을 일반화하지 않는다.
2. 100→125→100이므로 최종 순변화는0이다. 배율1.25×0.80=1에서1을 뺀 값이지 변화율 합0.05나 최종배율1이 아니다. 빈 변화열(배율의 항등원1)·한 번·상승/하락·순서역전·0·-100%를 금액 반복 갱신과 Fraction의 정확한 배율 곱으로 검증했다. 초기금액은 양수이며 비율 표현과 퍼센트 숫자를 혼동하지 않는다.
3. 정답 관측은6개 중4개로 accuracy≈0.667. 클래스0 재현율3/4와 클래스1 재현율1/2의 동일 비중 평균은0.625다. 일반 정확도 재사용·두 점수 순서 교환·양성 재현율만 쓰는 보기와 다르다. Counter 집계로 불균형/완전정답·오답/한종류 예측/레이블 이름 변경을 검증했다. 한 클래스의 모든 행을 같은 비율로 복제해도 balanced accuracy가 보존됨을 확인했다. 실제 두 클래스가 모두 존재하고 기본 adjusted=False이며 단일 클래스/예측에만 새 클래스가 있는 경계는 일반화하지 않는다.
4. EXCEPT의 오른쪽에 있는2와 NULL이 왼쪽에서 제외되고 중복1은 하나만 남는다. Python 집합 차이/SQLite 정렬(NULL 우선)로 빈 양쪽·오른쪽 빈표·중복·음수·한쪽/양쪽 NULL을 검증했다. 원본 입력에서 NOT IN이면 빈 결과라는 반례도 실행했다. 집합의 중복 판정과 WHERE의 NULL 삼값 논리를 구별한다. SQLite가 지원하지 않는 EXCEPT ALL로 설명하지 않는다.
5. id2 연결 한 행, a에만 있는id1, b에만 있는id3으로3행이다. INNER1/LEFT2/조건 없는 쌍4와 구별된다. 독립 행쌍 열거 후 양쪽 미연결 rowid를 보완해 빈 양쪽/한쪽·전체일치/불일치·중복키 다대다·NULL키를 대조했다. ON의 일반 등식은 NULL끼리 연결하지 않는다. SQLite3.39 이상이 지원하는 FULL OUTER JOIN이며 로컬 참조는3.53.1에서 실행했다. 실제 배포 원격 환경의 전체 참조 검증도 통과해야 게시한다.
