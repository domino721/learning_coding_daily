# 2026-10-18 · SQL 입력 보완과 새 문제 5개

WBS-350 유지보수, 설계/계획 1.5.0 유지. 사용자의 SQL 입력 누락 지적과 문제 수정·신규 작성·배포 요청에 따른다. Codex가 직접 편집·계산 검수하며 모델 API와 Gemini는 사용하지 않는다.

기존 `sql-where-02`, `sql-having-02`, `sql-count-02`, `sql-join-02`, `sql-join-03`, `sql-null-02`는 ID·쿼리·정답·보기·힌트·난이도를 유지하고, 표시 코드 앞에 전체 입력을 추가해 v1에서 v2로 올린다. 과거 해시 fixture는 변경하지 않는다. 테스트는 해당 여섯 문항의 새 입력과 버전만 되돌린 투영이 원본 해시와 같은지 검사한다. 나머지 기존 문항은 그대로 유지한다.

저장된 v1 문제는 기록을 덮어쓰지 않고, ID와 쿼리가 현재 보완본과 일치할 때만 화면에서 입력을 보충한다. 답안·시도·진도·원래 snapshot·백업·저장 키·origin은 유지한다. 풀이 화면과 과거 해설 화면에 같은 표시 규칙을 적용한다.

새 배치 `codex-2026-10-18`은 SQL 5개다. 사용자 지적에 관련된 집계·NULL 경계와 SQL 풀의 기초 집계/조건부 연결을 보완한다. 전체 보관 70개, 활성 Python 48개·SQL 17개, 보류 서술형 5개다.

모든 새 문제에 SQLite 입력 테이블·열·전체 행을 SQL 주석으로 제시한다. 첫 문제는 CREATE TABLE만 제공하고 지문에 행이 없음을 명시한다. 다른 문제는 NULL·중복·문자열을 포함한 모든 INSERT를 제공한다. 제목과 질문은 답을 미리 해석하지 않으며 두 힌트는 요청 시에만 제공한다. 보기는 빈 집합/모두 NULL 혼동, 분모 고정, DISTINCT 무시, 조건을 만족하지 않는 기존 주문을 혼동하는 오개념으로 구성했다. 시간·난이도는 편집 추정값이다.

`scripts/validate_sql_content.py`는 표시된 입력만 독립 SQLite에 만들고 쿼리를 실행한다. 참조 데이터가 있으면 전체 테이블·열·행이 같은지 검사하며, 객관식/단답의 출력이 정답과 같은지도 검사한다. 기존 compact/pipe 표도 읽으므로 SQL 18문항 전체에 적용된다. `export-content.py --check`에도 연결해 게시 시 입력 누락/불일치를 차단한다. `reference_setup`만 맞는 문제는 통과하지 못한다.

독립 경계 검사는 입력 0행/모두 NULL/중복/0값/혼합값에서 SUM·COUNT·AVG·DISTINCT를 직접 계산한 기대값과 대조한다. 외부 조인은 주문 0건/완료·미완료 혼합/한 고객의 중복 완료/NULL 상태를 고객 집합 계산과 대조한다. 입력을 생략하거나 합계가 같은 다른 행으로 바꾸거나 조인 테이블을 하나 빼도 검사가 실패함을 확인한다. 참조 실행은 저장소가 작성한 코드에만 적용하며 사용자 입력 코드는 실행하지 않는다.
