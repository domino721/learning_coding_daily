# 서비스 범위와 기록 책임 — ADR 011

2026-10-18 사용자 요청 및 기존 호스팅 없음이라는 답변에 따른 결정이다.

- 대상: Python 기초를 아는 개인이 모바일에서 데이터 분석 코드·조건·판단을 짧게 회상하는 무료 베타.
- 제공 성과: 풀이·도움·복습 이력과 다음 학습의 근거를 제공한다. 취업·자격·통계적으로 입증된 실력 향상은 보장하지 않는다.
- 공개 웹: 기존 GitHub Pages origin과 저장 키를 유지한다. 로컬 기록과 파일 백업으로 계속 사용할 수 있다.
- 계정: 선택한 HTTPS 서버에 사용자가 명시적으로 연결할 때만 기록을 전송한다. 외부 광고·분석 추적을 기본 사용하지 않는다.
- 데이터: 아이디, 비밀번호의 scrypt 해시, 해시된 복구 코드/토큰, 답안·문항 snapshot·진도·관찰 후기. 이메일·실명은 필수가 아니다.
- 계정 보안: 서버가 발급한 사용자 UUID로 DB를 선택한다. 다른 사용자 세션·백업을 읽거나 쓸 수 없다. 토큰은 24시간 만료하고 복구/삭제/로그아웃 때 폐기한다. 브라우저 토큰은 sessionStorage에 남으며 XSS로부터의 완전한 보호를 뜻하지 않는다. 개인 서버를 공개할 때 HTTPS와 운영 점검이 필요하다.
- 동기화: 먼저 기기에 저장하며 연결 후 변경을 서버와 병합한다. 실패하면 기기 기록을 유지하고 재전송한다. 충돌은 중단하고 두 기록을 보존한다. 현재는 소규모 베타용 전체 기록 교환이다.
- 삭제: 서버 계정 삭제는 운영 DB와 접근 토큰을 제거한다. 기기 기록·이전에 내보낸 파일·운영자가 보관한 백업은 별도다. 운영자는 백업 보존 기간을 정하고 삭제 요청을 백업 목록에도 반영해야 한다.
- 비용: 새 유료 계정·모델 API·호스팅을 생성하지 않는다. 컨테이너 실행 가능 상태와 실제 공개 서버 배포를 구분한다.
- 실제 관찰: WBS-520/530은 실제 휴대폰 7일 자료와 검토가 있을 때만 완료한다. 이번 구현에서 그 자료를 생성했다고 주장하지 않는다.

출시 게이트: 주요 검사 성공, 사용자/기기 격리, 정상/충돌 백업, 복원 연습, 실제 기기 관찰, 원격 보호 확인, 운영자·호스팅·지원 창구·보존 기간 확정. 현재 미보유인 공개 API 호스팅을 선택하기 전까지 계정 서버가 운영 중이라고 표시하지 않는다.

## 서버 실행과 운영

```bash
APP_REQUIRE_AUTH=1 APP_DB_PATH=.data/learning.sqlite3 APP_ALLOWED_ORIGINS=https://domino721.github.io uv run --frozen uvicorn backend.main:app --host 127.0.0.1 --port 8000
# 또는
docker compose up --build
```

컨테이너는 루프백 8000에만 바인딩한다. 공개 시 운영자의 HTTPS reverse proxy 뒤에 둔다. 허용 origin은 경로를 제외한 정확한 origin이며 와일드카드는 거절한다. 비밀번호는12~128자, 로그인/등록/복구는 IP당 분당15회로 제한한다. 다수 proxy/instance로 확장할 때 중앙 rate limit과 계정 저장소 전환을 검토한다. 현재 SQLite 구성은 단일 인스턴스·영속 볼륨을 전제로 한다.

브라우저에서 ‘나의 기록 → 선택한 서버에 계정 연결·동기화’를 연다. 본인 서버 주소와 아이디/비밀번호를 넣고 전송에 동의해 연결한다. 처음 표시한 복구 코드는 기기 밖에 보관한다. 서로 다른 계정의 기기 기록을 합치려면 먼저 파일 백업과 소유 확인이 필요하다.

## 백업·복구 연습

모든 인스턴스를 멈춘 상태에서 계정 디렉터리를 백업한다. 백업에는 비밀번호 해시와 답안이 포함되므로 디렉터리 접근을 제한하고 기기 밖 암호화된 저장소에 보관한다. 기본 권장 보존은 운영자가 채택한 경우에 한해 최근7일이며 자동 외부 업로드는 없다.

```bash
python3 scripts/account-backup.py --source .data/accounts --destination /safe/location/backup-YYYYMMDD
python3 scripts/account-backup.py --source /safe/location/backup-YYYYMMDD --destination /safe/location/restore-test --restore
```

복구 대상은 비어 있어야 한다. 체크섬·SQLite 무결성을 검사하고 기존 파일을 덮어쓰지 않는다. 복구 때 모든 토큰을 폐기해 재로그인을 요구한다. 복구 DB로 임시 서버를 띄워 로그인·과거 snapshot·중복 제출을 확인한 뒤 영속 볼륨 전환을 수행한다. 삭제 요청 이후의 오래된 백업을 운영에 복원하지 않는다. 배포 코드는 이전 이미지로 되돌릴 수 있지만 DB를 무조건 과거 버전으로 내리지 않는다.

GitHub 관리자 자격 증명을 갖춘 환경에서는 `bash scripts/protect-main.sh`로 강제 검사·PR·force-push 금지를 적용한다. 이 환경의 실제 관리 API PUT은 Forbidden이어서 원격 보호는 미적용이다. 적용 후 required context가 실제 품질 job 이름과 일치하는지 확인한다.
