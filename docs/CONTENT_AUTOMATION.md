# Codex의 일자별 문제 생성·검수·게시

기본 운영은 Codex 예약 실행이다. 매일 **한국 시간 오전 9시, 새 문제 총 5개**를 생성하며 모델 API 키·별도 호스팅을 필수로 두지 않는다. 이 분량은 기존 앱의 하루 학습 상한이 아니다. Gemini/Argon 교차 검수는 사용자의 지시에 따라 현재 생략하고 Codex 직접 검수와 실제 참조 계산으로 표시한다.

1. 최신 main·AGENTS.md·커리큘럼·WBS를 확인한다. 오래된 미커밋 초안은 백업하고 최신 배포본 위에 덮어쓰지 않는다.
2. 부족한 개념·수준과 Python/SQL 풀을 확인해 숫자만 바꾼 반복이 아닌 5문제를 작성한다. 지문·코드·보기·정답·힌트 2개·해설·참조 출력·난이도 근거·추정 시간을 갖춘다.
3. 날짜별 원본 `backend/content_batches/YYYY-MM-DD.json`에 저장한다. 같은 날짜 배치가 이미 있으면 중복 추가하지 않는다. `batch_id=codex-YYYY-MM-DD` 및 고유 문항 ID를 사용한다.
4. 직접 다시 풀고 실제 pandas/NumPy/SQLite/scikit-learn 참조 출력, 별도 경계 사례, 정답 유일성·편집 품질을 확인한다. 검수 전 배치는 게시하지 않는다. 저장소 소유 예제의 개발 테스트이며 사용자 코드를 API에서 실행하지 않는다.
   SQL은 모든 테이블의 열·전체 행·빈 테이블 여부를 풀이 전 코드 주석에 제시한다. `reference_setup`만으로 검수하지 않고 표시된 입력을 재구성해 같은 데이터와 출력인지 `scripts/validate_sql_content.py`로 확인한다.
5. `backend/difficulty.json`과 웹 내보내기를 함께 갱신한다. 기존 문항 ID/버전·snapshot·origin·저장 키·사용자 기록·트랙·추천 규칙을 보존한다. 콘텐츠·앱 검사와 새 문항의 모바일 풀이·기록 회귀를 검증한다.
6. 통과한 변경만 최신 main에 하나의 일관된 커밋으로 반영한다. 동시 변경은 비강제 갱신/expected SHA로 보존한다. 기존 Pages 작업과 실제 사이트의 해당 빌드를 확인한 뒤 성공을 알린다. 실패하면 정확한 단계를 보고한다.

검수·계산·모바일·배포의 근거는 날짜별 `docs/content_batches/`와 새 EV/작업 기록에 남긴다. 첫 배치 이후 같은 계약의 일상 배치는 WBS-350 유지보수 기록을 추가하며 매번 설계 기준선을 증가시키지 않는다. 계약이 바뀌면 새 CR·기준선을 사용한다.

현재 원격 main에는 모델 API 생성 cron이 없으며 기존 `.github/workflows/pages.yml`과 관리 검사만 유지한다. 예전 API 초안은 백업/stash에 보존했고 이 경로의 실행 의존성이 아니다. Codex 예약인 **매일코딩 문제 생성·검수·배포**를 변경·중지하면 정기 생성이 바뀐다. GitHub의 모델 API 활성화 변수는 이 예약을 제어하지 않는다.

최초 배치는 [2026-10-17 검수 기록](content_batches/2026-10-17.md), 작업 범위는 [현재 WBS](planning/WBS.md)에서 확인한다. 작성·로컬 검증·커밋·배포 완료는 구분하며 실제 학습 효과와 실기기 검증을 에뮬레이션 결과로 대신하지 않는다.
